# TASK_021 — Разделение предстоящих событий на независимые визуальные блоки

**Статус:** В РАБОТЕ.
**Основание:** ADR-004 (нет TASK — нет кода). Запрошено владельцем напрямую.
**Связана с:** [[TASK_019]] (общий компонент `UpcomingEventRow` и экран
`/upcoming-events`), [[TASK_020]]/[[TASK_020A]] (формат срока внутри строки
— не меняется).

---

## 1. Проблема

Несколько предстоящих событий («Ближайшие события» на Главной и полный
список на `/upcoming-events`) сейчас рендерятся внутри одного общего
`SummaryCard`, а соседние элементы разделяются горизонтальной чертой
(`bordered` проп `UpcomingEventRow` → `borderBottomWidth`). Визуально это
выглядит менее «воздушно», чем секция «Последние события», где каждое
событие — собственная карточка (`EventCard` на `SummaryCard`) с зазором
между карточками (`eventList: { gap: 11 }` в `app/(tabs)/index.tsx`).

## 2. Требуемое изменение

Каждое предстоящее событие/речь должно стать независимым визуальным
блоком:

- собственный фон и границы, соответствующие текущему дизайну
  (переиспользовать `SummaryCard` — тот же примитив, что и `EventCard`);
- небольшой вертикальный зазор до следующего элемента;
- без горизонтальной черты-разделителя между элементами;
- визуально похоже на карточки «Последние события».

Внутренняя раскладка каждого элемента не меняется: заголовок сверху;
дата снизу слева; срок («Через N мес M д.», «Сегодня» и т. д.) снизу
справа — весь код `relativeDays`/`formatDateDMY` (TASK_020/020A) не
трогается.

## 3. Область изменений

Общий компонент **сохраняется** — правится один раз, применяется в обоих
местах:

- `src/components/dashboard/UpcomingEventRow.tsx` — строка оборачивается в
  `SummaryCard` вместо `View`; проп `bordered`/стиль `rowBorder` убираются
  (черта больше не нужна).
- `src/components/UpcomingEventsCard.tsx` (Главная, секция «Ближайшие
  события») — общий оборачивающий `SummaryCard` вокруг списка убирается;
  элементы рендерятся в `View` с зазором (`gap`, то же значение, что и
  `eventList` в `app/(tabs)/index.tsx`); кнопка «Показать все» остаётся,
  но уже не внутри общей карточки.
- `app/upcoming-events.tsx` — то же изменение контейнера списка.
- Пустое состояние («Нет предстоящих событий») остаётся внутри одиночной
  `SummaryCard` в обоих местах — оно не список из нескольких элементов, и
  требование задачи (разделение *соседних* событий) на него не
  распространяется.

## 4. Вне области (не трогаем)

- Расчёт и сортировка дат, `upcomingItems()` (`src/data/constants.ts`).
- `relativeDays`/`formatDateDMY`/календарная арифметика TASK_020/020A.
- Контент событий, категории, навигация, лимит Главной (3), маршрут
  `/upcoming-events`.
- Секция «Последние события» / `EventCard` — только визуальный референс,
  код не трогаем.
- `AGENTS.md` — не трогаем ни при каких условиях.

## 5. Тесты

Существующие `src/components/__tests__/UpcomingEventsCard.test.tsx` и
`app/__tests__/upcomingEventsScreen.test.tsx` проверяют текстовое
содержимое и поведение (лимит, навигация, пустое состояние), не
структуру/черту — по чтению ожидается, что они останутся зелёными без
изменений. Новых тестов на чистую вёрстку (нет `describe`-специфики под
разделители) не требуется; при обнаружении обратного — обновить точечно.
