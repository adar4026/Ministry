# TASK_020 — Точный календарный срок до предстоящих событий

**Статус:** ЗАВЕРШЕНА — реализована и верифицирована локально.
**Основание:** ADR-004 (нет TASK — нет кода). Запрошено владельцем напрямую.
**Продолжение:** см. `docs/TASKS/TASK_020A_UPCOMING_EVENTS_COMPACT_REMAINING_TIME.md`
— компактный формат вывода `relativeDays()` поверх той же календарной
арифметики, без изменений в этом документе задним числом.

---

## 1. Проблема

Секция «Ближайшие события» на Главной и экран `/upcoming-events`
(TASK_019) показывали оставшееся время только в месяцах, округлённых
делением миллисекундной разницы на условные 30-дневные месяцы
(`Math.round(diffDays / 30)`). Например, событие через 2 полных месяца и
20 дней могло отображаться как «Через 3 месяца» — округление в большую
сторону, не привязанное к реальной длине конкретных календарных месяцев.

## 2. Ожидаемое поведение

- Оставшийся срок выражается полными календарными месяцами плюс
  остатком в днях, например: «Через 2 месяца 20 дней», «Через 1 месяц
  1 день», «Через 3 месяца 1 день».
- Если полных месяцев нет — показываются только дни: «Через 20 дней»,
  «Через 1 день» (включая «завтра» — см. §6).
- Если полные месяцы есть, а остаток дней равен нулю — дни не
  показываются («Через 2 месяца», без искусственного «0 дней»).
- Событие сегодняшним днём — `"Сегодня"` (поведение не менялось).
- Корректная русская плюрализация для месяцев и дней (1/2-4/5+,
  исключение 11-14, повтор паттерна на 21/22/25 и т. д.).
- Расчёт — календарный (полные календарные месяцы, затем остаток в
  днях), а не деление разницы в миллисекундах на 30.

## 3. Общий помощник

Изменения сосредоточены в уже существующем общем помощнике
`relativeDays()` (`src/data/constants.ts`) — единственном месте
форматирования оставшегося времени, которое уже переиспользуется и
Главной, и `/upcoming-events` через общий компонент строки
`UpcomingEventRow` (`src/components/dashboard/UpcomingEventRow.tsx`,
внедрён в TASK_019). Дублирования логики не было — новый отдельный
помощник не вводился, правится единственное существующее место.

## 4. Реализация

- `addMonthsClamped(start, n)` — прибавляет `n` целых календарных
  месяцев к дате, с клампингом дня месяца к длине целевого месяца
  (например, 31 января + 1 месяц → 28/29 февраля, без переноса в март).
  Локальный аналог одноимённой функции в `src/data/dateFormat.ts`
  (TASK_018, для прошедших дат) — здесь не переиспользуется напрямую,
  так как `relativeDays()` не нужно разбиение на годы, которое делает
  `calendarElapsed()`.
- `daysBetweenUTC(a, b)` — разница в целых днях между двумя календарными
  датами через `Date.UTC(...)`, без влияния времени суток или DST на
  результат.
- `relativeDays(dateISO, now)`: находит наибольшее число целых
  календарных месяцев от `today` (даты без времени), не превышающее
  целевую дату (тоже без времени), затем остаток в днях между
  получившимся «месячным якорем» и целью. Итог форматируется как
  «Через N месяцев» / «Через N месяцев M дней» / «Через M дней», с
  корректной русской плюрализацией через уже существующие `monthWord`/
  `dayWord`.
- Обе даты (`today`, целевая) нормализуются к календарным `Date` без
  времени суток перед любым сравнением — время дня и часовой
  пояс/переход на летнее время не могут сдвинуть результат на ±1 день
  (требование п.10 исходного задания).

## 6. Побочное изменение: убран специальный случай «Завтра»

Прежняя реализация `relativeDays()` для `diffDays === 1` возвращала
`"Завтра"`. Явное требование владельца для TASK_020 приводит пример:
«Через 1 день» для события завтрашним днём (п.5 исходного задания,
раздел «If there are no full months, display only the number of
days… "Через 1 день"»). Так как формат для «нет полных месяцев» теперь
единообразно — «Через N дней»/«Через 1 день», ветка `"Завтра"` удалена
как противоречащая новому явному примеру. Проверено: строка `"Завтра"`
не встречается больше нигде в кодовой базе — ни в других компонентах,
ни в тестах, ни в документации задач (`grep -rn "Завтра"` вне
`node_modules` — ноль совпадений до этого изменения). Конфликтующих
задокументированных требований не найдено.

## 6a. Найденный при проверке дефект и его устранение: срок конкурировал с заголовком за строку

Первая итерация фикса (`maxWidth: "55%"`, `flexShrink: 1`,
`textAlign: "right"` на стиле `relative`) устраняла перенос даты на
320×568, но срок оставался на одной визуальной линии с заголовком
(`flexDirection: "row"`, `justifyContent: "space-between"`) — при более
длинных календарных строках («Через 11 месяцев 29 дней») это
по-прежнему визуально конкурировало с заголовком за верхнюю строку.

**Итоговая раскладка (замена первой итерации, не дополнение):**
`UpcomingEventRow` перестроен на две строки:

- верхняя строка — только заголовок (`itemTitle`, `numberOfLines={1}`,
  получает всю ширину карточки, без соседней колонки);
- нижняя строка (`bottomRow`, `flexDirection: "row"`,
  `justifyContent: "space-between"`, `marginTop: 4`) — дата слева, срок
  справа.

Срок (`relative`) сохраняет `maxWidth: "55%"`/`flexShrink: 1`/
`textAlign: "right"` — при нехватке места переносится на свою вторую
строку, не задевая дату слева. Дата сдвинута из старой левой колонки в
`bottomRow` как есть (`marginTop: 2` убран — вертикальный отступ теперь
даёт `bottomRow.marginTop`). Изменение ограничено JSX-структурой и
стилями одного файла (`src/components/dashboard/UpcomingEventRow.tsx`)
— общего для Главной и `/upcoming-events`; карточка, кнопка «Показать
все», лимит 3 на Главной, структура `/upcoming-events` не изменены.
Редизайна карточки не производилось.

## 7. Тесты

`src/data/__tests__/constants.test.ts`, `describe("relativeDays…")`:

- полные месяцы + остаток дней (2 месяца 20 дней);
- 1 месяц и 1 день;
- только дни (без полных месяцев), включая «Через 1 день» (завтра);
- ровное число полных месяцев без «0 дней»;
- «Сегодня» для сегодняшней даты;
- переход через конец года;
- клампинг конца месяца (31 января + 1 месяц → 28 февраля, невисокосный
  год) — включая случай, когда клампинг даёт точное совпадение с целью
  («1 месяц», не «28 дней»);
- февраль и високосные годы;
- независимость от времени суток входной `now`;
- корректные русские формы для месяцев и дней, включая границы
  11-14/21/22/25.

## 8. Вне области (не трогаем)

- Редизайн карточек Главной и `/upcoming-events` — не делается;
  единственная UI-правка — перестройка `UpcomingEventRow` на две строки
  (§6a), понадобившаяся при визуальной проверке новых, более длинных
  строк, а не запланированная переработка карточки.
- Вкладка «События» (`/timeline`) — не использует `relativeDays()` для
  отображения, не затронута.
- Формат хранения даты (`YYYY-MM-DD`), модель данных, `StoreContext`.
- `upcomingItems()`, лимит Главной = 3, кнопка «Показать все» — без
  изменений (TASK_019).
