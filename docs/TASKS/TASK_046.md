### 3.3 Tab bar

- `app/(tabs)/_layout.tsx` — expo-router `Tabs` с полностью кастомным
  `tabBar={(props) => <TabBar {...props} />}` (не дефолтный react-navigation
  tab bar), `sceneStyle.paddingBottom: 90` (жёстко задано, без именованной
  константы).
- `src/components/TabBar.tsx` — плавающий pill-бар, `position: "absolute",
  bottom: 0` (строки 97-103), рендерится react-navigation как элемент,
  соседний с содержимым сцены (не вложен ни в один экранный `ScrollView`).
- Проверено вживую (dev-сервер, web, DOM-инспекция): `html`/`body`/`#root`
  уже имеют `overflow-y: auto`/`hidden` и НЕ скроллятся сами по себе
  (`document.documentElement.scrollTop` остаётся `0` даже при
  принудительной попытке проскроллить весь документ) — существующий
  сброс (`#root,body,html{height:100%}`, `body{overflow:hidden}`,
  `html,body,#root{overflow-x:hidden}`, `dist/index.html`) уже
  предотвращает document-level скролл/rubber-band на web. Каждый
  промежуточный `View` react-native-web рендерит с `position: relative`
  по умолчанию, поэтому цепочка предков `TabBar`'а от `#root` до самого
  бара целиком состоит из `position: relative`-контейнеров фиксированной
  высоты (`812px` = высота viewport) — абсолютное позиционирование бара
  корректно привязано к этой цепочке, а не к документу.
- Тем не менее описанное поведение («дёргается, плавает» при overscroll)
  — известный класс проблем на iOS Safari/PWA: momentum/rubber-band
  внутри самого скроллящегося `ScrollView`-div не двигает document
  (подтверждено выше), но `position: "absolute"` (в отличие от `"fixed"`)
  остаётся чувствителен к специфике мобильного Safari — изменению
  динамической высоты viewport при авто-скрытии адресной строки во время
  скролла, которое у `position:absolute`-элемента в цепочке `%`-высот
  может проявляться как видимое смещение на долю секунды, тогда как
  `position: "fixed"` привязывает элемент напрямую к видимой области
  окна браузера, не завися от пересчёта высоты родительских `%`-контейнеров.
  `react-native-web` (`^0.21.2`, уже в проекте) поддерживает `position:
  "fixed"` как проходное CSS-значение (используется, например, во
  внутренней реализации `Modal` самой библиотеки) — не является новой
  зависимостью.
- Решение: на web переключить `TabBar`'ный `wrap`-контейнер на
  `position: "fixed"` (`Platform.OS === "web"`), на native (iOS/Android)
  оставить `position: "absolute"` как есть — там `ScrollView`-bounce не
  затрагивает соседние `View` (стандартное, проверенное поведение RN,
  ADR-007 не требует менять нативное поведение, которое не воспроизводит
  баг). Визуально ничего не меняется на обеих платформах — меняется
  только механизм привязки.

## 4. Технические решения

1. **Фон:** `app/(tabs)/hours/index.tsx` переходит на тот же паттерн, что
   Главная/Профиль/События: корневой `View{flex:1, backgroundColor:
   DS.homeBase}` → `<HomeBackground />` → `ScrollView` с прозрачным фоном.
   `DS`/`HomeBackground` импортируются из `@/components/dashboard`
   (существующий экспорт, `src/components/dashboard/index.ts`) — новый
   похожий компонент не создаётся. `HOURS_COLORS.screenBackground`
   (`#EBEBEF`) становится неиспользуемым в этом файле; сам токен не
   удаляется из `hoursTokens.ts` (может использоваться где-то ещё —
   проверить перед удалением, вне обязательной части задачи).
2. **Карточки:** добавить `shadowColor/shadowOpacity/shadowRadius/
   shadowOffset/elevation` в `card`-стили `TimerHeroCard.tsx` и
   `HoursNavList.tsx`, значения — как у `HoursHeroCard`/`SummaryCard`
   (Главная), чтобы карточки визуально соответствовали Главной на новом
   градиентном фоне. Сам `backgroundColor` (`#FFFFFF`) не меняется — уже
   корректен.
3. **Отмена таймера:** добавить подтверждённое действие полной отмены,
   не изменяя семантику существующего «Отмена»/«Назад» в Save-форме
   (простое закрытие формы без потери данных остаётся как есть — «не
   менять существующую бизнес-логику без необходимости»). В экран паузы
   (`mode === "paused"`, без `showSave`) добавляется отдельный,
   низко-акцентный элемент «Отменить сессию» (текст-ссылка/кнопка,
   danger-стиль) — по нажатию показывает `Alert`/`confirmAsync()`-
   подтверждение («Отменить сессию? Время не будет сохранено.») и только
   при подтверждении вызывает уже существующий `discard()`. Паттерн
   идентичен уже проверенному в `recovery-screen`/`clock-rollback`
   (`app/(tabs)/hours/timer.tsx:105-110`). Меняются оба места, где
   пауза-без-Save отображается: `TimerHeroCard.tsx` и `timer.tsx`.
   `useTimer.ts`/`src/data/timer.ts` не меняются ни на строку — `discard()`
   уже делает всё нужное.
4. **Tab bar:** `src/components/TabBar.tsx` — `wrap`-стиль получает
   `position: Platform.OS === "web" ? "fixed" : "absolute"`. Больше
   ничего в файле не меняется. `sceneStyle.paddingBottom: 90`
   (`app/(tabs)/_layout.tsx`) не меняется — уже достаточен и не относится
   к причине бага.
