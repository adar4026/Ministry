## Проблема

Экран «События» (`app/(tabs)/timeline.tsx`, TASK_041/TASK_045) открывается
двумя большими плашками-кнопками («Добавить событие», «Добавить тему»),
которые занимают много вертикального пространства и отодвигают поиск,
темы и карточки вниз. Владелец прислал референс в духе «Заметки и теги»:
компактный заголовок с одной фирменной кнопкой `+` в углу, а не два ряда
широких кнопок.

## Цель

1. Убрать `actionsRow` (обе большие плашки) полностью.
2. В `pageHeader` — заголовок «События» / подзаголовок «Важные даты и
   мероприятия» остаются как есть; в правом верхнем углу того же блока —
   одна компактная круглая/скруглённая кнопка `+` (44×44 минимум,
   фирменный синий `DS.accent`, лёгкая тень), не наезжающая на текст на
   узком iPhone.
3. По нажатию `+` открывается новый bottom sheet `AddActionSheet`
   (`src/components/timeline/AddActionSheet.tsx`) — заголовок «Добавить»,
   два действия («Добавить событие» — иконка календаря, «Добавить тему» —
   новая иконка тега `TagIcon`), каждое ведёт на уже существующий,
   неизменённый функционал:
   - «Добавить событие» → `router.push('/add?focus=event')` (тот же
     маршрут/форма, что использовался старой кнопкой, TASK_045 §2);
   - «Добавить тему» → открывает существующую модалку создания темы
     (`Modal` + `addCustomCategory`, TASK_045 §3) — не переписывается.
   Закрытие: свайп вниз (`PanResponder`+`Animated`, без новых
   зависимостей — оба API есть в `react-native`), тап по затемнённому
   фону, кнопка `✕` (тот же паттерн, что `ProfileEditSheet`). Лёгкий
   haptic (`expo-haptics`, уже используется в `WheelPicker.tsx`) на
   открытие и на выбор действия, с `.catch(() => {})` — не роняет
   поведение там, где Haptics недоступен (web). Фон под открытым sheet не
   прокручивается — тот же примитив `RNModal`, что уже используют
   `Modal.tsx`/`ProfileEditSheet.tsx` на этом же экране.
4. Темы (фильтр) — по референсу «компактная переносимая сетка чипов»,
   без горизontal-scroll (переиспользуется уже существующий `ChipSelector`,
   `flexWrap: "wrap"` у него уже есть, TASK_045 §5 «уточнение»):
   - Основной ряд (всегда виден), фиксированный порядок: `Все`,
     `Публичные`, `Пионер`, `Назначения`, `Переезд`, `Школы`, `Личное`,
     `Конгрессы` — первые семь идентифицируются по системному
     value-ключу (`all`, `talk`, `pioneer`, `appointment`, `move`,
     `school`, `personal`), «Конгрессы» — единственный элемент,
     идентифицируемый по названию пользовательской темы (создаётся
     владельцем через ту же форму, что и любая другая тема; если такой
     темы ещё нет — просто не появляется в основном ряду, без ошибки).
   - Кнопка «Все темы (N) ▾» под основным рядом, всегда видна, где `N` —
     `customCategories.length` (динамическое число тем, созданных
     владельцем). По нажатию раскрывает остальные темы (системная
     «Событие» + любая пользовательская тема, кроме «Конгрессы», включая
     будущие) в такой же переносимой сетке чипов; повторное нажатие
     сворачивает. Стрелка поворачивается на 180° при раскрытии (не
     меняет глиф).
   - Если выбранный фильтр относится к скрытой теме (например, открыт по
     ссылке/восстановлен), блок автоматически раскрывается, чтобы выбор
     оставался видимым.
   - Ни одна тема не удаляется/переименовывается/не меняет `id` —
     затронута только группировка чипов на этом экране.
5. Нижняя плавающая навигация (`TabBar.tsx`, TASK_054/055/057) —
   не изменяется.

## 6. Правка после первичной проверки — отступ перед «Все темы (N)»

Владелец отметил после деплоя: под последней строкой чипов (`Личное /
Конгрессы`) оставался слишком большой пустой промежуток перед кнопкой
«Все темы (N)» — «почти ещё один пустой ряд». Измерено в браузере
(мобильный 375×812, воспроизведено с `N=3`): расстояние от нижнего края
последнего чипа до кнопки составляло `10px` (`topicsSection.gap`) `+ 4px`
(`moreTopicsBtn.paddingVertical`) ≈ `14px` — заметно больше, чем `6px`,
которым чипы отделяются друг от друга внутри самого `ChipSelector`
(`chipRow.gap`, `src/components/ui.tsx`).

Правка — только числовые отступы, без изменения порядка/размера/стилей/
логики чипов, счётчика `N`, раскрытия/сворачивания, поиска, кнопки `+`,
`AddActionSheet` и карточек:
- `topicsSection`: `gap: 10 → 6` (совпадает с `chipRow.gap`, кнопка
  читается как ещё одна строка той же сетки, а не отдельный блок),
  `marginBottom: 14 → 12` (карточки событий начинаются выше).
- `moreTopicsBtn`: `paddingVertical: 4` убран (реальный отступ теперь
  ровно `gap: 6`, без скрытого дополнительного паддинга); вместо
  визуального паддинга — `hitSlop={6}` на `Pressable`, чтобы тач-таргет
  остался комфortным без увеличения видимого отступа.

Повторное измерение: отступ от нижнего края чипа до кнопки — ровно `6px`
(было ~14px), при раскрытом «Все темы» — тот же `6px` между сеткой
скрытых тем и кнопкой. Наложений на чипы нет ни на 375px, ни на desktop.
