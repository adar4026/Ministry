# TASK_027 — Длительность под датой + янтарный акцент в карточках событий

**Статус:** РЕАЛИЗОВАНА, верифицирована локально. Коммит/push/деплой —
ожидают отдельного подтверждения владельца.
**Основание:** ADR-004 (нет TASK — нет кода). Запрошено владельцем напрямую.
**Связана с:** [[TASK_025]] (унификация типографики даты и компактный формат
длительности — база, на которой строится эта задача), [[TASK_021]] (карточки
событий как независимые `SummaryCard`), [[TASK_026]] (прецедент: общий
компонент меняется целиком на обоих экранах, где используется, по прямому
подтверждению владельца).

---

## 1. Запрос владельца

Красный цвет длительности воспринимается как ошибка/просрочка/опасность —
заменить на тёплый янтарно-оранжевый (`#D97706`). Одновременно перенести
длительность под дату (вертикально), убрать разделитель `·`.

- «Ближайшие события»: `Конгресс Мадрид` / `04-09-2026` / `Через 1 мес. 16 д.`
- «Последние события»: `Переезд в Хихон, Астурия` / `09-05-2024` /
  `2 г. 2 мес. 10 д.`

Типографика (уточнение владельца после первой формулировки задачи):
длительность — **тот же `fontSize`, что и дата**, не размер названия;
отличие от даты — только цветом и, при необходимости, насыщенностью
шрифта (`fontWeight`).

## 2. Аудит (до изменений)

Ровно два места рендерят дату+длительность в карточках событий Главной:

| Компонент | Файл | Где используется | Layout до |
|---|---|---|---|
| `UpcomingEventRow` | `src/components/dashboard/UpcomingEventRow.tsx` | Home «Ближайшие события» (через `UpcomingEventsCard.tsx`) **и** отдельный экран `/upcoming-events` | Одна строка: дата слева, `relativeDays()` справа (`justifyContent: space-between`), `relative` — `fontSize:15, fontWeight:700, color: COLORS.blue` |
| `EventCard` | `src/components/dashboard/EventCard.tsx` | Home «Последние события» | Одна строка (с переносом всей длительности как атомарного блока при нехватке места, TASK_025): `` `date · elapsed` ``, `elapsed` — `fontSize:13, color: DS.metaText` |

`UpcomingEventRow` — общий компонент. Владелец подтвердил (см. диалог
реализации): применить новую раскладку **к обоим местам** — Home-превью и
`/upcoming-events` — вместо форк-разветвления на два разных вида одной и
той же карточки (аналогично прецеденту TASK_026 для `MonthChip`).

`/timeline` использует собственный, давно устоявшийся паттерн дат
(`timeElapsed()`, независимые стили) вне системы карточек Home
(`SummaryCard`) — не входит в область этой задачи, не трогается.

## 3. Решение

### 3.1 Новый цветовой токен

Добавлен `DS.durationAccent = "#D97706"` в
`src/components/dashboard/tokens.ts` — единственное место, где живёт этот
цвет; оба компонента импортируют его оттуда (`UpcomingEventRow` раньше не
импортировал `DS`, теперь импортирует, как и её сосед `EventCard`).
Существующие `DS.amber`/`DS.amberInk` (`#ff8a1e`/`#c2610a`) — цвет кольца
цели (`HeroProgressRing`), другое значение и другая семантика — не
переиспользуются и не трогаются.

### 3.2 `EventCard.tsx` («Последние события»)

- `metaText` (контейнер даты+длительности): `flexDirection: "row"` →
  `"column"`, `flexWrap` убран (не нужен — каждая строка не делит ширину с
  соседней), добавлен `gap: 2` (небольшой вертикальный интервал дата↔длительность).
  `alignItems: "baseline"` убран (был нужен только для строчной раскладки).
- Разделитель `` ` · ${elapsed}` `` → просто `{elapsed}` (без `·`, без
  ведущего пробела).
- `elapsed`: `fontSize: 13` → `14` (равно `date`), `lineHeight: 19` (равно
  `date`), `fontWeight: "600"` (насыщеннее даты, но меньше и без заглавных —
  визуально слабее `title` 16/600), `color: DS.metaText` →
  `DS.durationAccent`.
- `metaRow` (дата+длительность слева, `Badge` справа): `alignItems`
  `"flex-end"` → `"center"` — с двумя строками текста вместо одной
  центрирование даёт более сбалансированное соседство с бейджем, чем
  прижатие к нижнему краю; бейдж по-прежнему в своей колонке
  (`justifyContent: "space-between"`), не пересекается с текстом ни при
  каком количестве строк.
- `date`, `title`, `dot`, `Badge` — без изменений.

### 3.3 `UpcomingEventRow.tsx` («Ближайшие события» + `/upcoming-events`)

- Импорт `DS` из `./tokens` (аналогично `EventCard`).
- `bottomRow` (была строка: дата слева / срок справа) → `View` с
  `flexDirection: "column"`, `gap: 2`, `marginTop: 4` (без изменений
  относительно заголовка). Убраны `justifyContent`/`alignItems: flex-start`
  строчной раскладки — не нужны для колонки.
- `relative` (переименовать в коде оставлено как есть — то же имя стиля,
  смысл не изменился, только раскладка): `fontSize: 15` → `14` (равно
  `date`), добавлен `lineHeight: 19` (равно `date`), `fontWeight: "700"` →
  `"600"` (соответствие требованию «тот же размер, отличие — цвет и при
  необходимости насыщенность»; 700 при равном с датой размере читался бы
  слишком тяжело рядом с 600-м заголовком), `color: COLORS.blue` →
  `DS.durationAccent`, `textAlign: "right"`/`maxWidth: "55%"`/`flexShrink: 1`
  убраны (были нужны только когда длительность делила строку с датой и
  могла столкнуться с ней; в колонке длительность имеет всю ширину карточки
  и переносится нативно, без обрезания).
- `date`, `itemTitle` — без изменений (сохранён приглушённый
  серо-синий `COLORS.muted`).

### 3.4 Не трогаем

- `/timeline` — собственный паттерн, не часть этой задачи.
- Формат даты (`formatDateDMY`, `ДД-ММ-ГГГГ`), `calendarElapsed`,
  `formatElapsedRu`, `relativeDays` — бизнес-логика расчёта и текст
  длительности не менялись, только цвет/раскладка/размер шрифта.
- Категорийные элементы `EventCard` (точка, `Badge`, цвета категорий,
  обрезание длинных заголовков `numberOfLines={1}` на `title`) — без
  изменений.
- Кнопка «Показать все», пустое состояние `UpcomingEventsCard` — без
  изменений.
- Глобальная палитра `COLORS` (`src/data/constants.ts`) — не менялась,
  новый цвет живёт только в локальных `DS`-токенах Home (см. комментарий в
  `tokens.ts` о разделении областей).

## 4. Тесты

`src/components/dashboard/__tests__/EventCard.test.tsx` и (если существует)
аналогичный тест `UpcomingEventRow`/`UpcomingEventsCard` — обновлены под:
отсутствие `·` перед длительностью, длительность и дата — отдельные текстовые
узлы (уже было так для `EventCard` после TASK_025; для `UpcomingEventRow`
структура рендера не менялась — были и остаются два `Text`).

- Нет миграции схемы хранения — `mj_events_v1`/`mj_talks_v1` не

## 7. Результат

Проверки: `npx tsc --noEmit` — чисто; `npx jest` — **395/395**, 31 сьют (без
изменения количества — задача не меняет тестируемое поведение форматтеров,
только раскладку/цвет); `expo export --platform web` — успешно, 24
статических маршрута (без изменений). Визуальная проверка (dev-сервер на
своём порту 8082, существующие в браузере тестовые события этой сессии —
включая максимальный пример `09-09-2015`/«Назначение»/`10 г. 10 мес. 10
дн.` из TASK_025 — без записи в данные владельца) на 320×900, 375×900,
428×900: Главная («Ближайшие события», «Последние события») и
`/upcoming-events` — дата и длительность отображаются друг под другом,
без `·`, длительность — янтарным (`#D97706`), тем же размером шрифта, что
и дата; badge в «Последних событиях» не пересекается с текстом ни на одной
ширине; `document.documentElement.scrollWidth === window.innerWidth` на
всех трёх ширинах; `document.body.innerText` не содержит `…`; консольных
ошибок нет. `/timeline` проверен отдельно — использует свой собственный,
не тронутый этой задачей паттерн (`timeElapsed()`, полнословные единицы
«6 мес.», «1 лет 8 мес.» — не путать с `formatElapsedRu()`, затронутым
только внутри `EventCard`).

Коммит/push/деплой — **не выполнялись**, ожидают отдельного подтверждения
владельца.
