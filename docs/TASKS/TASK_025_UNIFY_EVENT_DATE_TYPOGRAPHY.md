# TASK_025 — Унификация типографики полной даты в карточках событий

**Статус:** ЗАВЕРШЕНА — реализована, задеплоена и проверена в проде.
**Основание:** ADR-004 (нет TASK — нет кода). Запрошено владельцем напрямую
как небольшая корректировка утверждённой типографики TASK_023.
**Связана с:** [[TASK_023]] (типографическая шкала — не откатывается за
пределами описанной корректировки), [[TASK_022]] (формат `ДД-ММ-ГГГГ` — не
меняется), [[TASK_021]] (карточки событий как независимые `SummaryCard` —
компоновка сохраняется).

---

## 1. Проблема

Полная дата в карточках раздела «Ближайшие события» отображалась заметно
крупнее и читаемее полной даты в карточках раздела «Последние события» —
визуальное несоответствие внутри одного экрана (Главная), обнаруженное
владельцем после TASK_023.

## 2. Аудит (до любых изменений)

Найдены два независимых места, рендерящих пользовательский формат полной
даты (`ДД-ММ-ГГГГ`) в карточках событий:

| Компонент | Файл | Где используется | `date` до изменения |
|---|---|---|---|
| `UpcomingEventRow` | `src/components/dashboard/UpcomingEventRow.tsx` | Home «Ближайшие события» (через `UpcomingEventsCard.tsx`) и экран `/upcoming-events` | `fontSize: 14`, `fontWeight` не задан (default), `lineHeight` не задан |
| `EventCard` | `src/components/dashboard/EventCard.tsx` | Home «Последние события» | `fontSize: 13`, `fontWeight` не задан, `lineHeight` не задан; длительность склеена в тот же `Text`/стиль, что и дата |

`/timeline` рендерит `formatDateDMY` в собственном давно устоявшемся
паттерне (timeline-рейка, независимые `date`/`elapsed` стили 12px/11px) —
не часть системы карточек Home (`SummaryCard`), не упомянут ни в TASK_021,
ни в TASK_023 как часть Home card system → сознательно не включён в
унификацию (подтверждено владельцем).

## 3. Реализованное решение

### 3.1 Унификация типографики даты

Эталон — типографика `UpcomingEventRow` (крупнее, читаемее). Оба
компонента приведены к идентичным `fontSize: 14, fontWeight: "400",
lineHeight: 19` (19 — по прецеденту проекта: 13px→18, 15px→21 в
`BackupSection.tsx`/`hours/timer.tsx`, интерполяция для 14px). Цвета
(`COLORS.muted` в `UpcomingEventRow`, `DS.metaText` в `EventCard`) —
намеренно не унифицированы: задача касалась только `fontSize`/
`fontWeight`/`lineHeight`.

### 3.2 Компактный формат длительности

`formatElapsedRu()` (`src/data/dateFormat.ts`) — единственный форматтер,
формирующий длительности вида `"1 год 10 месяцев 10 дней"` — переведён с
полнословных грамматических форм (`pluralRu`/`YEAR_FORMS`/`MONTH_FORMS`/
`DAY_FORMS`) на фиксированные сокращения без склонения: `"г."`/`"мес."`/
`"дн."`. Пример: `"2 года 2 месяца 3 дня"` → `"2 г. 2 мес. 3 дн."`. Один
обычный пробел между числом и сокращением, один между частями — без
двойных пробелов, запятых или широких разделителей. Нулевые юниты
по-прежнему опускаются (логика не менялась). `pluralRu`/`pluralYearsRu`/
`pluralMonthsRu`/`pluralDaysRu` не удалены — самостоятельные протестированные
утилиты, использовавшиеся раньше только внутри `formatElapsedRu`; экспорт
и тесты на грамматику (`21`/`22`/`25` и т.п.) сохранены отдельно.

`formatElapsedRu` используется **только** в `EventCard.tsx` → Home
«Последние события». `/upcoming-events` и Home-превью используют
`relativeDays` (другой лейбл, не затронут); `/timeline` использует
отдельную `timeElapsed()` из `constants.ts` — не тронута.

Интервал вокруг `·` в `EventCard` сокращён с двойного до одинарного
пробела с каждой стороны.

### 3.3 Перенос длительности на вторую строку (320px)

Даже с компактным форматом строка «дата · длительность» не помещалась на
320px для событий с 3-юнитной длительностью (`N г. N мес. N дн.`) в паре с
более длинным бейджем категории («Назначение») — точные измерения см. §4.
Вместо `ellipsis` (`numberOfLines={1}` на общем `Text`) `metaText` в
`EventCard.tsx` переведён на `View` с двумя `Text`-соседями
(`flexDirection: "row", flexWrap: "wrap", alignItems: "baseline"`). RN по
умолчанию не сжимает flex-элементы (`flexShrink: 0`), поэтому при нехватке
места вся `elapsed`-строка (со своим ведущим `·`) целиком уходит на вторую
строку как единый блок — дата никогда не разбивается изнутри, длительность
никогда не обрезается многоточием. Если места достаточно (375/428px или
короткая длительность на 320px) — обе части остаются в одну строку, без
дополнительного кода для этого случая (естественное следствие
`flexWrap`).

```ts
metaText: { flex: 1, flexDirection: "row", flexWrap: "wrap", alignItems: "baseline" },
date: { fontSize: 14, fontWeight: "400", lineHeight: 19, color: DS.metaText },
elapsed: { fontSize: 13, color: DS.metaText },
```

## 4. Точные измерения (320px, до решения о переносе)

Реальный рендер (dev-сервер, `numberOfLines={1}` — версия до переноса на
вторую строку), `scrollWidth` vs `clientWidth` строки «дата · длительность»
внутри карточки:

| Карточка | Доступно, px | Нужно, px | Переполнение |
|---|---|---|---|
| `15-01-2026 · 6 мес. 4 дн.` | 166 | 166 | 0 |
| `02-11-2024 · 1 г. 8 мес. 17 дн.` | 186 | 189 | 3 px |
| `08-03-2022 · 4 г. 4 мес. 11 дн.` | 193 | 195 | 2 px |
| `09-09-2015 · 10 г. 10 мес. 10 дн.` (максимальный пример) | 192 | 207 | 15 px |

Доступная ширина зависит от ширины бейджа категории в той же строке —
после перехода на `flexWrap` эта разница в доступной ширине больше не
влияет на видимость даты/длительности: не помещающаяся длительность просто
переходит на вторую строку целиком.
