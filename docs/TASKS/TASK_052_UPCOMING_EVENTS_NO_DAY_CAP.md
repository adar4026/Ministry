# TASK_052 — Снять ограничение по дням для «Через N дней»

**Статус:** завершено, задеплоено (коммит `feat(events): show all
countdowns`, по решению владельца)
**Область:** только верхняя граница диапазона, в котором показывается
относительный срок (`src/data/dateFormat.ts`), плюс комментарии в
`UpcomingEventRow.tsx`, отражающие новое поведение.
**Не входит:** порядок метаинформации (TASK_051), двухцветная разметка
(TASK_050), структура карточек, расчёт `diff`/`daysBetweenUTC`, пороги
`Сегодня`/`Завтра`/`Просрочено`, изменения компонента (он уже был готов к
этому — см. §2).

---

## 1. Цель

До этой задачи `upcomingDateLabel()` показывал `Через N дней` только для
`diff` от 2 до 30 дней включительно (`RELATIVE_HORIZON_DAYS = 30`); дальше
— откат на голую календарную дату без относительной фразы вообще
(`primary` = дата, `secondary` = `null`, `days` = `null`). По ТЗ владельца
у **каждого** будущего события (кроме `Сегодня`/`Завтра`) теперь должны
быть оба элемента — `дата · Через N дней` — независимо от того, насколько
далеко оно отстоит, как это уже было для первых карточек (TASK_050/051).

Примеры из ТЗ (все относительно `2026-08-20`, фикстура TASK_048–051):

| Дата события | `primary` | `secondary` |
|---|---|---|
| `2026-09-22` (33 дня) | `Через 33 дня` | `22 сентября` |
| `2026-10-11` (52 дня) | `Через 52 дня` | `11 октября` |
| `2026-11-28` (100 дней) | `Через 100 дней` | `28 ноября` |
| `2027-01-09` (142 дня, следующий год) | `Через 142 дня` | `9 января 2027` |

`Сегодня`, `Завтра`, `Просрочено` — без изменений (их код-путь не тронут).

## 2. `src/data/dateFormat.ts`

`RELATIVE_HORIZON_DAYS` (константа-порог `30`) удалена вместе с веткой
`if (diff <= RELATIVE_HORIZON_DAYS) {...} return {...без Через...}`.
Единственная оставшаяся ветка для `diff >= 2` теперь безусловна:

```ts
return {
  primary: `Через ${diff} ${pluralDaysRu(diff)}`,
  secondary: absolute,
  urgency: diff <= SOON_DAYS ? "soon" : "upcoming",
  days: diff,
};
```

`SOON_DAYS` (порог `7`, разделяющий `soon`/`upcoming`) не менялся — он
по-прежнему участвует в `urgency`, но, как и раньше (TASK_050), сам
`urgency` больше не определяет цвет `Через N дней`-строки: цвет для неё
всегда `DS.navy` (слова) + `DS.todayInk` (число), независимо от тира.

Побочный эффект: `urgency: "later"` для валидной даты теперь недостижим —
эта ветка раньше как раз и обозначала «дальше 30 дней». `"later"` остаётся
только в fallback для нераспознаваемого `iso` (`!m`) — оставлено как
defensive-значение, чтобы `URGENCY_COLOR` (`UpcomingEventRow.tsx`) не
терял тотальность по типу `Record<UpcomingUrgency, string>`.
`daysBetweenUTC`, `formatDateHuman`, `pluralDaysRu`/`pluralRu` — не
менялись.

## 3. `UpcomingEventRow.tsx`

Функциональных изменений нет — компонент уже переключается на
двухцветный рендер по `label.days != null` (TASK_050), а этот флаг теперь
просто выставляется для куда большего диапазона `diff`. Обновлены только
комментарии, отражавшие старую 30-дневную границу как всё ещё
действующую (у `URGENCY_COLOR`, у `styles.statusRow`'s `flexWrap`-пример).
