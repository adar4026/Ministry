## 1. Что было

Над крупным значением часов отдельной строкой шёл eyebrow
`СЕНТЯБРЬ 2026` (uppercase, 13/17, 700). Он дублировал дату из шапки
(`Воскресенье, 20 сентября`). От низа шапки до верха цифры набиралось
63 px: `heroBlock.gap 22` + `HomeHero.wrap.paddingTop 18` + eyebrow 17 +
`figure.marginTop 6`. Сама цифра — `46/52, fontWeight 800,
letterSpacing −1.2`, единица «ч» тем же кеглем и весом, что и число —
тяжёлый, утилитарный вид; hero читался как «прижат к левому краю с
пустотой сверху».

## 2. Что нужно

1. Убрать `СЕНТЯБРЬ 2026` целиком, без пустого места на его месте.
2. Поднять блок часов: пересобрать вертикальные интервалы, чтобы цифра
   начиналась заметно выше и была композиционно связана с шапкой; hero
   компактнее; нижние элементы (progress, темп, метрики, кнопки) — с
   прежними интервалами.
3. Типографика цифры — современный iOS-dashboard: число крупнее и чуть
   легче по весу (без тяжёлого 800), аккуратный lineHeight, «ч» (и «м»)
   меньше и легче, второстепенно, на одной базовой линии с числом.
   Системный шрифт, без декоративного.
4. Значение — главный визуальный центр верхнего блока (базовое левое
   выравнивание сохраняется — это архитектура текущей композиции).

## 3. Реализация

### 3.1 Вертикальная композиция

| Слой | Было | Стало |
|---|---|---|
| `index.tsx` `heroBlock.gap` (шапка → HomeHero) | 22 | 14 |
| `HomeHero` `wrap.paddingTop` | 18 | 0 |
| eyebrow `СЕНТЯБРЬ 2026` | 13/17 + `figure.marginTop 6` | удалён |
| `figure` line box | 52 | 60 |
| `caption.marginTop` | 2 | 0 |
| `track.marginTop` / `pace` / `metrics` / `actions` | 14 / 8 / 14 / 16 | без изменений |

Расстояние «низ даты → верх line box цифры»: 63 → 14 px; с учётом
внутреннего leading цифры визуальный зазор ≈ 20 px — цифра читается как
продолжение шапки, не как отдельный блок. Высота сцены считается по
`onLayout` (TASK_065), поэтому WebGL-фон автоматически укоротился вместе
с контентом; `HERO_CONTENT_TOP`/`HERO_TAIL` не менялись.

### 3.2 Типографика цифры (`HomeHero.figure*`)

`formatHMRounded()` не тронут — его строка (`37 ч`, `1 ч 30 м`)
разбирается на пары «число + единица» и рендерится вложенными `<Text>`
в одном родителе (одна базовая линия на native и web):

| Роль | Стиль |
|---|---|
| число | `fontSize 56`, `fontWeight 700`, `letterSpacing −1.6`, `MINISTRY.ink`, `tabular-nums` |
| единица «ч» / «м» | `fontSize 24`, `fontWeight 600`, `letterSpacing −0.2`, `MINISTRY.ink2` (второстепенный ink) |
| контейнер | `lineHeight 60`, `numberOfLines 1`, `adjustsFontSizeToFit`, halo-тень как раньше |

Число стало крупнее (46 → 56) и легче (800 → 700), единица — меньше
и вторична; ширина «1 ч 30 м» на 320 pt помещается без ужатия (~205 px).

### 3.3 Доступность

Единая озвучиваемая сводка hero (`accessibilityLabel` на обёртке) по-
прежнему начинается с месяца и года — визуальный eyebrow ушёл, но
контекст в озвучке сохранён.

## 8. Исправление: центрированный KPI (по замечанию владельца)

**Замечание к `db5c82f`:** на production `37 ч` всё ещё читался как старый
левый показатель — прижат к левому краю, цифры тяжёлые, `ч` «приставлена»
с зазором, блок не стал визуальным центром hero; «поднять выше» ≠ «по
центру».

**Что изменено (только блок цифры, `HomeHero.tsx`):**

| | Было (`db5c82f`) | Стало |
|---|---|---|
| положение | в левой сетке, от `padding 16` | отдельный wrapper `figureWrap` (`width 100%`, `alignItems/justifyContent center`) — цифра по горизонтальному центру экрана; **только** она, caption и всё ниже — в левой сетке |
| число | `56 / 700 / −1.6` | `60 / 600 / −1.5`, `lineHeight 64` — medium, не bold |
| единица | `24 / 600`, `marginLeft 5` | `24 / 500`, `marginLeft 2` — «37 ч» как одна конструкция |
| шрифт | системный | web: `ui-rounded, -apple-system, …` → SF Rounded в iOS Safari/PWA, иначе системный; native — системный. Зависимостей нет |
| вертикаль | date → box 14 px | `figureWrap.marginTop 8` (+ `heroBlock.gap 14`) → date → box 22 px, визуально до верха цифры ≈ 32 px (ориентир 28–36) |
