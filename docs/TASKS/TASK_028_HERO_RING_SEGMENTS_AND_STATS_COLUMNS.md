# TASK_028 — Сегментированное декоративное кольцо + симметричные колонки метрик

**Статус:** РЕАЛИЗОВАНА, верифицирована локально. Коммит/push/деплой —
ожидают отдельного подтверждения владельца.
**Основание:** ADR-004 (нет TASK — нет кода). Запрошено владельцем напрямую,
с референсным изображением.
**Связана с:** [[TASK_016]] (текущий `HeroProgressRing`/двухэлементная
строка метрик — база, на которой строится эта задача), [[TASK_015]]

## 1. Запрос владельца

Карточка месячного прогресса Главной (`HoursHeroCard.tsx`):

1. Заменить одноцветное кольцо (`HeroProgressRing`, зелёный/синий/янтарный
   градиент, интерполирующий по проценту) на декоративное трёхсегментное
   кольцо — зелёный/синий/красный, зелёный крупнее всех, синий второй,
   красный — маленький акцент; равномерные промежутки; закруглённые концы
   дуг; в центре — процент, по-прежнему из реальных данных.
2. Перестроить нижний блок «Осталось / 13 дней» на две равные по ширине
   (50/50) колонки с центрированным содержимым и вертикальным разделителем
   строго посередине; правая колонка получает подпись «До конца» (по
   собственной рекомендации владельца — для симметрии с левой).

## 2. Аудит (до изменений)

внутренняя строка метрик `HoursHeroCard.tsx` (`statsRow`/`statsGrid`) —
оба используются **только** в `HoursHeroCard.tsx`, который, в свою очередь,
рендерится только на Главной (`app/(tabs)/index.tsx`). Подтверждено
`grep`: `HeroProgressRing` — 0 других мест использования; `HoursHeroCard` —
0 других мест использования. `GoalRing.tsx` — независимый, никем не
используемый (кроме упоминания в комментарии `HeroProgressRing.tsx`)
компонент-сосед, задуманный как отдельная реализация для будущего
потребителя (см. исходный комментарий TASK_015) — не трогается. Других
затронутых экранов нет.

## 3. Интерпретация референсного изображения

Присланное изображение (кольцо с числом «71» в центре) показывает три
цветные дуги (тёмно-зелёная/сине-зелёная, красная, синяя), суммарно
покрывающие заметно меньше окружности, чем можно было бы ожидать от
71%-го заполнения одним сплошным дуговым индикатором (как было в старой
реализации `colorForPct`/`dash = pct/100 * circumference`). Это
подтверждает явную формулировку задачи — «цветные сегменты являются
визуальным оформлением одного общего прогресса, а не тремя отдельными
показателями» — и означает: **сегменты кольца фиксированы по размеру и не
масштабируются от процента**; единственный элемент, реально
рассчитываемый из данных — число в центре. Ранжирование размеров
(зелёный > синий > красный) в реализации соответствует явному
текстовому требованию владельца, а не визуальным пропорциям на маленьком
референсном скриншоте (где синий сегмент казался крупнее зелёного) —
это расхождение сознательно решено в пользу текста задачи.

## 4. Решение

### 4.1 `HeroProgressRing.tsx` — сегментированное декоративное кольцо

- Убрана вся логика `colorForPct`/`hexToRgb`/`mixHex` (интерполяция цвета
  по проценту, единая дуга) — прогресс теперь не определяет ни цвет, ни
  длину дуг.
- Три отдельных `<Circle>` (та же техника, что и раньше — `strokeDasharray`
  + `rotation` в градусах на общей окружности), с равными зазорами между
  ними и `strokeLinecap="round"` на каждом (закруглённые оба конца каждой
  из трёх дуг):
  - зелёный (`DS.green`, `#34c759`) — 159° (крупнейший),
  - синий (`DS.accent`, `#3f6fe0`, существующий акцентный синий приложения)
    — 106° (второй по размеру),
  - красный (`DS.danger`, `#dc2626`, уже существующий токен — «отставание
    от темпа» на этой же карточке) — 53° (маленький акцент),
  - 3 равных зазора по 14° (14×3 + 159 + 106 + 53 = 360°).
- Существующий сплошной светло-серый фоновый круг (`DS.ringTrack`) —
  оставлен без изменений позади сегментов; это и есть «более светлая
  фоновая дуга», которую просил добавить владелец «если это соответствует
  существующему стилю» — она уже существовала до этой задачи и
  сознательно не продублирована/не переопределена под каждый сегмент
  отдельно (что усложнило бы компонент без ясной пользы при полностью
  фиксированной, не зависящей от данных геометрии).
- Текст процента в центре — **без изменений** в логике (тот же
  `displayValue`/`fontScaleForDigits`/защита от `NaN`/`Infinity`/
  отрицательных значений); по-прежнему принимает `pct` и вычисляется из
  реальных данных `HoursHeroCard`.
- Размер (`size`, по умолчанию `48`) и толщина обводки (`size * 0.19`) —
  не изменены, компактность кольца сохранена.
- Пропсы компонента (`pct`, `size`) — не изменены, вызов в
  `HoursHeroCard.tsx` не требует правок сигнатуры.

### 4.2 `HoursHeroCard.tsx` — симметричные колонки метрик

- `statsGrid` — было `flexDirection: row, alignItems: center,
  justifyContent: space-between` (у `StatItem` — `flexShrink: 1`, без
  гарантии равных 50/50 колонок); стало: два `View` с `flex: 1,
  alignItems: "center"` (равная ширина, центрированное содержимое) вокруг
  вертикального разделителя (`statDivider`, без изменений в толщине/
  высоте/цвете) — разделитель гарантированно строго посередине именно
  потому, что оба соседних `View` теперь имеют одинаковый `flex: 1` вместо
  разной естественной ширины содержимого.
- Правому `StatItem` добавлена подпись `label="До конца"` (раньше —
  без подписи) — по прямой рекомендации владельца, ради симметрии между
  колонками; часть общей структуры `StatItem`, изменений компонента не
  потребовалось.
- `StatItem.value` (`Text`) получил `adjustsFontSizeToFit`/
  `minimumFontScale={0.8}` в дополнение к уже существовавшему
  `numberOfLines={1}` — защитная адаптивность на случай непривычно
  длинного значения (например, крупный «Осталось» в часах), без изменения
  видимого размера шрифта для типичных значений (`"7 ч 30 м"`, `"13 дней"`
  и т.п., которые короче доступной ширины колонки на всех проверенных
  экранах и не подвергаются сжатию).

## 9. Результат

Проверки: `npx tsc --noEmit` — чисто; `npx jest` — **396/396**, 31 сьют
(было 395/395 — +1 тест на подпись «До конца»); `expo export --platform
web` — успешно, 24 статических маршрута (без изменений). Визуальная
проверка (dev-сервер на порту 8082, временные тестовые сессии этой сессии
— `0%`/пустая цель и `85%`/`42 ч 30 м` из цели 50 часов, без записи в
данные владельца) на 320×900, 375×900, 428×900: кольцо не деформируется
(3 сегмента: зелёный крупный, синий второй, красный маленький акцент, с
равными зазорами и закруглёнными концами), геометрия сегментов идентична
на `0%` и `85%` (подтверждает: сегменты декоративные и не зависят от
данных — меняется только число в центре); центр кольца — измеренный SVG
не даёт смещения текста; нижние колонки — измеренный центр вертикального
разделителя совпадает с измеренным центром всего блока метрик (`320px`:
160/160; `428px`: 214/214); `"7 ч 30 м"`/`"13 дней"` и подписи «Осталось»/
«До конца» — на одном вертикальном уровне (`getBoundingClientRect().top`
совпадает попарно); нет переноса на две строки, нет обрезания; высота
карточки не выросла (не появилось новых строк, только перегруппировка
существующего блока); `document.documentElement.scrollWidth ===
window.innerWidth` на всех трёх ширинах; консольных ошибок нет (только
предсуществующее SVG-предупреждение `transform-origin`, не связанное с
этой задачей — см. TASK_017/023).

Коммит/push/деплой — **не выполнялись**, ожидают отдельного подтверждения
владельца.
