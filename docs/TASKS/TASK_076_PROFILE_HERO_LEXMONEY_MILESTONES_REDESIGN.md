## 1. Что было

`ProfileHeroCard.tsx` (TASK_042) рендерил три вехи бок о бок в равных
колонках внутри белой карточки с тенью (`SummaryCard`): заголовок каждой
колонки — мелкая (10px) серая подпись КАПСОМ, под ней дата и «стаж».
Владелец прислал референс — экран профиля приложения LexMoney (светлый
ледяно-голубой фон, мягкое стекло, простые строки «подпись слева —
значение справа», без отдельных карточек на строку) — и попросил
переработать блок по тому же принципу, включая верхнюю часть (аватар +
имя), но без баланса и без иконки-глаза.

## 2. Что изменено

Полная замена вёрстки `ProfileHeroCard.tsx` (данные и их источник —
`profile.events`, `useStore()` — не менялись):

1. **Шапка** — аватар (56px) слева, имя + подпись «Личный профиль»
   столбцом справа от него, шеврон `›` в конце строки (было: аватар 72px
   и имя, оба по центру, без подписи и шеврона).
2. **Вехи — три строки, не три колонки**: подпись (`ev.title`, как ввёл
   владелец, без uppercase) слева, значение (дата + «стаж») справа, все
   значения на одной вертикали (`justifyContent: space-between` +
   `flexShrink: 0` на колонке значения). Между строками — тонкий
   полупрозрачный разделитель (`StyleSheet.hairlineWidth`), после
   последней строки разделителя нет; никакой рамки/карточки на строку.
3. **Поверхность** — один плоский `View` (`styles.surface`) без тени и
   без border: `PROFILE_ICE.bg` (светлый ледяно-голубой, `#EAF3FF` при
   88% непрозрачности) + мягкий `backdropFilter: blur(18px)` на web (тот
   же приём, что `PILL_GLASS`/`NAV` уже используют в проекте — на native
   просто откатывается к плоскому цвету, backdrop-filter там не
   поддерживается). Заменяет старую `SummaryCard` (белый фон + тень
   0.04/16/6 + elevation 2).
4. **Типографика**: подпись строки — вторичный цвет, вес 500 (была
   uppercase, 10px, вес 700); значение (дата) — основной цвет, вес 600
   (было 700, тот же вес что у подписи); «стаж» под датой — вторичный
   цвет, вес 500.
5. **Пустое состояние** и **«+ Добавить событие»** сохранены (третье —
   вне поверхности, тем же accent-цветом, что и раньше), но пустое
   состояние теперь тоже рендерится на той же ice-blue поверхности вместо
   старой белой карточки — во всём компоненте не осталось смешения старого
   и нового оформления.
6. **Ограничение на 3 события** (`MAX_EVENTS`) теперь явно применяется в
   самом рендере (`profile.events.slice(0, MAX_EVENTS)`), а не только
   отражается в условии для «+ Добавить событие» — на старой раскладке
   ограничение обеспечивалось перебором `[0,1,2]`; новая построчная
   раскладка без явного `slice()` отрендерила бы все события, если бы их
   вдруг оказалось больше трёх (тест поймал это, см. §3).

### 2.1 Новые токены (`tokens.ts`)

```
export const PROFILE_ICE = {
  bg: "rgba(234,243,255,0.88)", // #EAF3FF, почти непрозрачный
  ink: "#15171C",
  ink2: "#5f6b80", // см. §2.2 — затемнено от референса ради AA
  divider: "rgba(120,135,155,0.12)",
} as const;
```

Осознанный one-off кластер (по образцу `FIGURE_GLASS`/`NAV`), явно
прокомментирован как ТОЛЬКО для этого блока — фирменный teal/mint
Ministry (`MINISTRY`) нигде больше не меняется; TASK_065 отдельно
фиксировал, что Ministry намеренно НЕ ледяно-голубой, как Lexcar/
LexMoney — это решение не отменяется, просто для одного конкретного блока
владелец попросил взять чужой референс один в один.

### 2.2 Контраст вторичного текста

Референс владельца — `#697386` (вторичный текст). На сведённом
(flattened) фоне `PROFILE_ICE.bg` поверх экранного mint-градиента это
даёт контраст **4.26:1** — чуть ниже WCAG AA (4.5:1) для обычного текста.
Затемнено до `#5f6b80` (тот же холодный серо-синий оттенок) — **4.81:1**,
проходит AA. Тот же прецедент, что `DS.subInk` (TASK_048): подпись
референса — отправная точка, финальное значение — ближайшее к ней,
которое проходит контраст.
