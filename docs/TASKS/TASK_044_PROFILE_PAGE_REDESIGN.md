# TASK_044 — редизайн страницы «Профиль»

## Цель

Полностью привести `app/(tabs)/profile.tsx` к визуальному языку Главной
страницы: тот же фон (`HomeBackground`/`DS.homeBase`), белые скруглённые
карточки на базе существующего `SummaryCard`, единый стиль иконок в
строках настроек, объединённый раздел «Данные и резервные копии». Без
изменения бизнес-логики (экспорт/импорт/резервное копирование,
редактирование профиля, навигация).

## Текущее состояние

`profile.tsx` — плоский `ScrollView` на глобальном `COLORS.bg`, без
своего фона/шапки; `ProfileHeroCard` уже построена на `SummaryCard`
(TASK_042) и уже соответствует стилю карточек Главной — трогать её не
нужно, только контекст вокруг неё. Остальные секции — локальный `Row`/
`SectionCard` на `COLORS.card`/`COLORS.border` (серые тяжёлые контейнеры,
не токены `DS` Главной). `BackupSection.tsx` — два отдельных кнопки
экспорта/импорта в ряд + абзац описания + баннер обратной связи + модал
предпросмотра импорта.

## Реализация

1. **Фон и шапка.** `screen: {flex:1, backgroundColor: DS.homeBase}` +
   `<HomeBackground />` — тот же приём, что уже использует Главная и
   `/timeline` (TASK_041), без копии компонента. Лёгкий заголовок
   страницы («Профиль» + короткий подзаголовок) в стиле заголовка «Часы»
   — обычный текст над контентом, без отдельной тяжёлой карточки.
2. **`ProfileHeroCard`** — не трогается функционально; уже `SummaryCard`
   + уже использует общий `ProfileAvatar` (TASK_043). Изменений нет.
3. **Новый `src/components/profile/ProfileSettingsRow.tsx`** — общая
   строка настроек (иконка в цветном чипе, заголовок, необязательный
   подзаголовок, справа — шеврон/значение/спиннер), стиль по образцу
   `HoursNavList` (`src/components/hours/HoursNavList.tsx`), но на
   токенах `DS` (Главная), а не `HOURS_COLORS`. Возвращает `View` без
   `onPress`, `Pressable` — с ним; сам не рисует внешнюю белую карточку —
   помещается внутрь `SummaryCard` с `style={{padding:0,
   overflow:"hidden"}}`, который и даёт скругление/тень/белый фон.
4. **`src/components/icons.tsx`** — 9 новых минималистичных line-иконок
   в существующем стиле (24×24, `stroke`, без внешней библиотеки):
   `BellIcon`, `TargetIcon`, `PaletteIcon`, `GlobeIcon`, `DownloadIcon`,
   `RefreshCwIcon`, `CloudIcon`, `InfoIcon`, `MessageIcon`. Существующие
   `CalendarIcon`/`ChartIcon`/`ClockIcon` переиспользуются напрямую для
   «Календарь служения»/«Статистика»/«История изменений».
5. **`BackupSection.tsx`** — та же логика (`handleExport`,
   `handlePickImport`, `handleConfirmImport`, `handleCancelPreview`,
   весь стейт, `Modal` предпросмотра импорта) без изменений; меняется
   только разметка триггеров: вместо абзаца-описания и двух кнопок в ряд
   — две `ProfileSettingsRow` («Экспорт данных» / «Резервная копия») с
   `accessibilityLabel`, **сохранённым буквально** таким же, как раньше
   (`"Экспортировать данные"` / `"Импортировать данные"`), чтобы не
   ломать существующие тесты, которые ищут кнопки по этим меткам.
   Новый необязательный проп `last` (по умолчанию `true`) управляет
   нижней границей второй строки — `profile.tsx` передаёт `last={false}`,
   потому что следом идёт строка «Синхронизация».
6. **`profile.tsx` — секции.** `SectionHeader` (уже есть, 23px/`DS.navy`,
   уже используется Главной для заголовков разделов) + `SummaryCard`
   (`padding:0, overflow:"hidden"`) с рядами `ProfileSettingsRow`.
   **Окончательный порядок разделов страницы (уточнение владельца после
   первой реализации):**
   1. Верхняя карточка профиля (`ProfileHeroCard`, не меняется).
   2. «Настройки» — те же 6 пунктов, тот же порядок и тот же
      `soon()`-хендлер: Уведомления / Цели / Календарь служения /
      Статистика / Оформление / Язык, каждый с иконкой.
   3. «Данные и резервные копии» — `BackupSection` (2 строки,
      `last=false`) + строка «Синхронизация» («Скоро — через A-Lex
      Core», без действия) — одна карточка вместо двух разрозненных.
   4. «О приложении» — версия (значение справа, без действия), «История
      изменений», «Обратная связь» — тот же `soon()`. Остаётся последним
      смысловым блоком страницы.

   Первая реализация располагала «Данные и резервные копии» сразу после
   карточки профиля, перед «Настройками» — владелец попросил переставить
   разделы местами до финализации задачи; сам состав и содержимое каждой
   секции не изменились, изменился только порядок отображения. Пункт
   «Календарь служения» в «Настройках» остаётся одной строкой (как и
   было реализовано и протестировано) — в уточнении владельца он был
   перечислен двумя отдельными строками списка («Календарь» / «Служения»),
   что похоже на артефакт форматирования (отдельного пункта «Служения»
   в проекте не существует); при необходимости владелец может уточнить
   отдельно.
7. **Нижняя навигация** — не трогается, общий `TabBar`/`Tabs` из
   `app/(tabs)/_layout.tsx` уже работает одинаково для всех вкладок.
