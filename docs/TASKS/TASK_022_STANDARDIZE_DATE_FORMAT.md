# TASK_022 — Единый формат отображаемой даты по всему приложению

**Статус:** ЗАВЕРШЕНА — реализована, задеплоена и проверена в проде.
**Основание:** ADR-004 (нет TASK — нет кода). Запрошено владельцем напрямую.
**Связана с:** [[TASK_018]]/[[TASK_020]]/[[TASK_020A]] (существующий корректный
`formatDateDMY` в `src/data/dateFormat.ts`, откуда и берётся эталон формата).

---

## 1. Проблема

Обычная полная календарная дата (`ДД-ММ-ГГГГ`), показываемая пользователю,
сейчас форматируется **тремя разными способами** в разных местах
приложения:

1. **`src/data/dateFormat.ts` → `formatDateDMY()`** — корректный,
   `"YYYY-MM-DD" → "DD-MM-YYYY"` (дефис). Используется только в
   `EventCard.tsx` («Последние события» на Главной).
2. **`src/data/constants.ts` → `formatDateDMY()`** — **другая функция с тем
   же именем**, даёт `"DD/MM/YYYY"` (слэш). Используется в ~9 местах:
   `UpcomingEventRow.tsx` (Главная «Ближайшие события» и
   `/upcoming-events`), `timeline.tsx` («События»), `hours/history.tsx`,
   `hours/timer.tsx`, `hours/month/[key].tsx`, `SessionRow.tsx`,
   `TodayCard.tsx`.
3. **Ручная сборка через `.split("-").reverse().join(".")`** в
   `src/components/stats/ProjectionCard.tsx` — даёт `"DD.MM.YYYY"` (точка),
   поле «Конец месяца» на экране статистики.
4. **Ручная сборка через `pad()`+точки** в
   `src/components/settings/BackupSection.tsx` → `formatBackupTimestamp()`
   — даёт `"DD.MM.YYYY HH:MM"` (точка в дате), поле «Создана» в
   предпросмотре импорта бэкапа.

Ни `toLocaleDateString`, ни `Intl.DateTimeFormat` в проекте не используются
— локале-зависимого форматирования дат нет, но обнаруженные три разных
сепаратора (`-`, `/`, `.`) сами по себе создают несогласованность.

Дополнительно: три формы добавления/редактирования с полем полной даты —
`EventForm.tsx`, `TalkForm.tsx`, `SessionForm.tsx` — используют обычный
`TextField`, **напрямую связанный с сырым ISO-значением** (`"YYYY-MM-DD"`,
плейсхолдер `"2026-06-28"` / `"ГГГГ-ММ-ДД"`). Пользователь и вводит, и видит
дату в формате ISO — то же исключение из «единого видимого формата»,
которое требует задача.

`RecordForm.tsx` — только год (`TextField`) + месяц (`ChipSelector`), не
содержит полной календарной даты; вне области.

## 3. Общий форматтер

Канон — уже существующий, корректный `formatDateDMY()` в
`src/data/dateFormat.ts`. Ничего нового с тем же назначением не создаётся.

- **Удаляется** дублирующая (ошибочная, слэш) реализация `formatDateDMY()`
  в `src/data/constants.ts`; вместо неё —
  `export { formatDateDMY } from "./dateFormat";` — так все ~9 существующих
  мест, импортирующих `formatDateDMY` из `@/data/constants`, продолжают
  работать без изменения путей импорта, но реально существует только одна
  функция.
- `src/data/dateFormat.ts` дополняется двумя новыми чистыми функциями
  (нужны для форм, см. §4):
  - `isValidDMY(s: string): boolean` — проверка формы `ДД-ММ-ГГГГ` (только
    формат, как и прежняя `isISODate`/`dateValid` в формах — без проверки
    календарной корректности, поведение не ужесточается).
  - `parseDMYToISO(dmy: string): string` — обратное преобразование,
    строковое (без `Date`/часового пояса); некорректный ввод возвращается
    без изменений (как и `formatDateDMY` для невалидного ISO).
- `src/components/stats/ProjectionCard.tsx` — `.split("-").reverse().join(".")`
  заменяется на `formatDateDMY(projection.goalDate)`.
- `src/components/settings/BackupSection.tsx` → `formatBackupTimestamp()`
  — дата-часть строится через `formatDateDMY(toISODate(d))` вместо ручной
  сборки через точки; часть времени (`HH:MM`) не меняется.

## 4. Формы: видимое `ДД-ММ-ГГГГ`, внутреннее ISO

Существующий паттерн проекта для дат в формах — обычный `TextField`,
**не** нативный `<input type="date">`, **не** date-picker компонент. Задача
прямо запрещает заменять рабочий picker на текстовое поле «только если это
уже не установившийся паттерн проекта» — здесь текстовое поле уже и есть
установившийся паттерн, замены picker'а не происходит.

Для `EventForm.tsx` / `TalkForm.tsx` / `SessionForm.tsx`:

- Локальное состояние `date` хранит **видимую** строку `ДД-ММ-ГГГГ` (то,
  что показывает и принимает `TextField`), а не ISO.
- Начальное значение при редактировании — `formatDateDMY(initial.date)`;
  при создании — `""` (`EventForm`/`TalkForm`, как и раньше) или
  `formatDateDMY(toISODate(new Date()))` (`SessionForm`, вместо прежнего
  сырого `toISODate(new Date())`).
- Валидация — `isValidDMY(date)` вместо прежней ISO-регулярки.
- Конвертация в ISO — **только один раз, в момент `submit()`**, через
  `parseDMYToISO(date)`, непосредственно перед вызовом `onSave(...)`; тип
  пропа `onSave` (`EventInput`/`TalkInput`/`SessionInput`, все с `date:
  string` = ISO) не меняется.
- Плейсхолдер/подпись поля — `"Дата (ДД-ММ-ГГГГ)"` / пример
  `"28-06-2026"` вместо прежних `"Дата (ГГГГ-ММ-ДД)"` / `"2026-06-28"`.
- Ни `keyboardType`, ни multiline, ни остальная разметка полей не меняются.

Это не вводит часовых поясов и не проходит через `Date` — оба
преобразования (`formatDateDMY`/`parseDMYToISO`) чисто строковые
(regex + перестановка групп), день/месяц/год никогда не пересчитываются
через `new Date(...)`, риска сдвига календарного дня нет.

## 5. Вне области (не трогаем)

- Расчёт/сортировка/фильтрация дат, календарная арифметика TASK_020.
- `relativeDays`/`timeElapsed`/`calendarElapsed`/`formatElapsedRu` —
  относительные фразы.
- Формат бэкапа, имя файла экспорта, схема хранения, миграции.
- `RecordForm.tsx` (год/месяц, не полная дата).
- Маршруты и их query-параметры (`?date=`, `/hours/month/[key]`) — ISO,
  технический контракт, не текст для пользователя.
- `AGENTS.md`.

## 8. Результат

- `npx tsc --noEmit` — чисто; `npx jest` — **30 сьютов, 385 тестов** (было
  28/359 — добавлено 2 сьюта: `EventForm.test.tsx`, `TalkForm.test.tsx`, +
  новые кейсы в `dateFormat.test.ts`/`SessionForm.test.tsx`/
  `BackupSection.test.tsx`); `npx expo export --platform web` — успешно, 24
  статических маршрута (без изменения количества).
- Визуальная проверка (dev-сервер, временные тестовые события/сессии, без
  записи в данные владельца) на 375×812 и desktop: Главная («Ближайшие
  события», «Последние события»), `/upcoming-events`, `/timeline` (список +
  «Редактировать событие»), `/hours/history`, `/hours/entry` (плашка «Дата»
  по умолчанию), `/add` → «Добавить событие» (до выбора — пустое поле с
  плейсхолдером `28-06-2026`; после ввода `05-08-2026` — сохранение, запись
  появляется в `/timeline` как `05-08-2026`; повторное открытие на
  редактирование показывает то же `05-08-2026`, календарный день не
  сдвинулся), экран статистики («Конец месяца»: `31-07-2026`, было
  `31.07.2026`) — везде дефис, ни одной точки/слэша/ISO-порядка;
  консольных ошибок нет (кроме предсуществующего несвязанного
  `transform-origin`-предупреждения).
- Финальный поиск по репозиторию: `toLocaleDateString`/`Intl.DateTimeFormat`
  — 0 вхождений; `formatDateDMY` — ровно одна реализация
  (`src/data/dateFormat.ts`) + один ре-экспорт (`src/data/constants.ts`);
  прежних `.split("-").reverse().join(".")` и ручной сборки через точки —
  0 вхождений; все оставшиеся `getFullYear()/getMonth()/getDate()` —
  внутренняя календарная арифметика, ISO-сборка, метки месяца/года («Июль
  2026») или имя файла бэкапа — не полная пользовательская дата.
- Временные тестовые данные (`mj_events_v1`/`mj_talks_v1`/`mj_sessions_v1`/
  `mj_records_v1` в localStorage dev-сервера) удалены после проверки.
- Коммит `fix(dates): standardize display format`, запушен в `origin/main`;
  локальный HEAD == `origin/main`. Деплой — `npm run deploy`. Подробности
  (хеши, бандл, прод-проверка) — `docs/STATUS.md`.
