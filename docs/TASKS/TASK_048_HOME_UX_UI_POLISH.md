## 2. Карточка цели («Христианская жизнь» / месячная норма)

### 2.1 Сохраняемая информация (без изменений математики)

`33 ч` · `из цели 50 часов` · процент · опережение/отставание ·
осталось часов · дней до завершения · переход в детали · добавление часов.
Все значения по-прежнему приходят из `monthProgress()` / `MONTHLY_GOAL` /
`computePaceDeviation()` — ни одна формула не менялась.

### 2.2 Прогресс: одна графическая шкала

Кольцо (`HeroProgressRing`) и горизонтальная шкала показывали один и тот же
процент. **Решение:** горизонтальная `progress-bar` — единственный
графический индикатор; кольцо из карточки удалено, процент показан текстом
`66% выполнено` рядом с ключевым результатом (`33 ч`).

`HeroProgressRing.tsx` **не удаляется**: это самостоятельный примитив
библиотеки `components/dashboard` со своим тест-файлом, как и `GoalRing`.
Из Главной убран только его вызов.

Фиктивные метрики темпа не добавлялись — в модели нет данных, кроме уже
используемого `computePaceDeviation()`.

### 2.3 Статус темпа

`Опережение на 0 ч 45 м` сохранён, математика не тронута. Цвет:
опережение — зелёный, отставание — предупреждающий (красный), «по плану» —
нейтральный. Все три цвета заменены на AA-контрастные токены (см. §5).

### 2.4 Компактность

Целевое сокращение высоты карточки — 15–20 % без фиксированных пиксельных
значений и без потери адаптивности. **Измерено на живом dev-сервере
(375×812): 241 → 204 px, −15,4 %.**

- убраны лишние вертикальные зазоры между блоками;
- блок «Осталось / До конца» переведён с двухстрочных элементов
  (подпись над значением) на однострочные (подпись + значение в строку);
- кольцо убрано, процент ушёл в строку ключевого результата;
- touch-targets кнопок сохранены и увеличены (`hitSlop` 8 → 10), тексты —
  с `numberOfLines` и `adjustsFontSizeToFit`, где они уже были;
- на экранах уже 360 pt блок «Осталось / До конца» возвращается к
  двухстрочной форме (`STAT_STACK_BREAKPOINT`) — обе колонки одновременно,
  чтобы не получить «одна колонка перенеслась, соседняя нет».

### 2.5 Две кнопки «Добавить»

Проверено: дублирования сценариев **нет** — это разные маршруты.

| Кнопка | Маршрут | Назначение |
|--------|---------|-----------|
| центральная «+» в нижней панели | `/add` | глобальное добавление: месяц (часы), событие, речь |
| кнопка в карточке цели | `/entry` | быстрое добавление часов (Manual Time Entry) |

**Решение:** кнопку в карточке оставить (она контекстная), но снять
неоднозначность подписи: видимый текст `Добавить` → `Добавить часы`
(совпадает с уже существовавшим `accessibilityLabel`). Центральная кнопка
остаётся глобальным действием и не меняется.

`Детали` — вторичное текстовое действие с chevron-иконкой
(`ChevronRightIcon` вместо текстового `›`). Карточка целиком остаётся
некликабельной (она и раньше не была `Pressable`) — чтобы не конфликтовать
с двумя отдельными кнопками внутри неё.

## 3. Ближайшие события

### 3.1 Структура карточки

- заголовок — только название события (`item.title`), без склейки с датой
  и суммой;
- дата/срочность — отдельная строка под заголовком;
- вертикальная плотность снижена (одна строка статуса вместо двух).

### 3.2 Сумма и валюта — решение

В модели `MinistryEvent` (`src/types/index.ts`) полей суммы и валюты **нет**:
`{ id, date, title, category }`. Условие ТЗ («если в модели события есть
отдельные поля суммы и валюты») не выполняется, поэтому:

- сумма **не** отображается отдельным полем;
- сумма **не** извлекается регулярными выражениями из произвольного
  названия (прямой запрет ТЗ);
- существующие записи с суммой внутри названия не ломаются — заголовок
  рендерится как есть.

Добавление `amount`/`currency` в модель — это расширение схемы данных
(типы + `EventForm` + timeline + backup/миграция), т.е. отдельная задача,
а не UI-полировка. Вынесено в «Следующие шаги».

### 3.3 Единый человеческий формат дат на Главной

Новые чистые функции в `src/data/dateFormat.ts`:

```
formatDateHuman(iso, now)  -> "4 сентября" | "4 сентября 2026" (год — если он не текущий)
upcomingDateLabel(iso, now) -> { primary, secondary, urgency }
```

Правила `upcomingDateLabel`:

| Условие | primary | secondary | urgency |
|---------|---------|-----------|---------|
| дата в прошлом | `Просрочено` | человеческая дата | `overdue` |
| сегодня | `Сегодня` | — | `today` |
| завтра | `Завтра` | — | `tomorrow` |
| 2–7 дней | `Через N дней` | человеческая дата | `soon` |
| 8–30 дней | `Через N дней` | человеческая дата | `later` |
| > 30 дней | человеческая дата | — | `later` |

Формат `20-08-2026` на карточках Главной больше не используется.
`formatDateDMY()` (TASK_022) остаётся каноническим для форм, истории,
таймера, timeline и профиля — контракт TASK_022 для них не меняется.
Отклонение зафиксировано именно как Home-scoped.

### 3.4 Срочность — цвет + текст

Цвет вторичен: текст статуса (`Просрочено` / `Сегодня` / `Завтра` /
`Через N дней`) понятен сам по себе. Цвета:

| urgency | токен |
|---------|-------|
| `overdue` | `DS.danger` (error) |
| `today` | `DS.warnInk` (warning) |
| `tomorrow`, `soon` | `DS.tealInk` (менее сильный акцент) |
| `later` | `DS.subInk` (нейтральный вторичный) |

### 3.5 «Последние события»

Формат даты унифицирован с §3.3 (`20 августа 2026` вместо `20-08-2026`).
Дата и прошедшее время снова в одной строке, но **переносящейся**
(`flexWrap`): на 375 pt это одна строка, на 320 pt — автоматически две.
Ограничение TASK_027 (метка длительности читается размером даты, никогда
размером заголовка) не менялось; жёсткое разбиение на две строки было там
средством от наложения на узком экране — `flexWrap` решает ту же задачу без
постоянной потери высоты. Разделитель `·` вложен внутрь `Text` метки, чтобы
не оставаться «сиротой» в конце первой строки при переносе.

Измерено: карточка «Ближайшие события» 95 → 71 px (−25 %),
карточка «Последние события» 95 → 70 px (−26 %).

## 4. Верхняя и нижняя зоны

### 4.1 Верх

`app/(tabs)/_layout.tsx` красил область top safe-area в `COLORS.bg`
(`#f8fafc`) — на iPhone над градиентом Главной появлялась пустая светлая
полоса. Фон `SafeAreaView` стал зависящим от маршрута: на Главной это
`HOME_GRADIENT[0]` — тот же цвет, с которого начинается `HomeBackground`,
поэтому статус-бар и шапка читаются как одна композиция. Контент
по-прежнему не заходит под системные элементы (`edges` не менялись).

Отступ `paddingTop` контента Главной уменьшен (16 → 10).

### 4.2 Низ

`sceneStyle.paddingBottom` был захардкожен в `90`. Реальная высота панели —
`TAB_BAR_HEIGHT` (высота бара) + `insets.bottom`: на iPhone с home-indicator
это 65 + 34 = 99 > 90, т.е. нижний контент уходил под панель.

`src/components/TabBar.tsx` теперь экспортирует:

```
TAB_BAR_HEIGHT            // высота самого бара, без safe-area
TAB_BAR_CONTENT_GAP       // безопасный визуальный зазор
useTabBarContentInset()   // TAB_BAR_HEIGHT + insets.bottom + TAB_BAR_CONTENT_GAP
```

`TAB_BAR_HEIGHT` = 67 (paddings + border + иконка + gap + lineHeight
подписи); `useTabBarContentInset()` читает `SafeAreaInsetsContext` напрямую,
а не `useSafeAreaInsets()`, — последний бросает исключение без
`SafeAreaProvider`, а хелпер отступов не должен ронять дерево в
изолированных тестах экрана.

Распределение ответственности:

- **Главная** — `sceneStyle.paddingBottom = 0`, отступ живёт в
  `contentContainerStyle` самого `ScrollView`. Фон Главной идёт до нижнего
  края экрана, контент прокручивается под плавающей панелью (шва между
  фоном Главной и полосой за панелью больше нет), последний элемент
  гарантированно выше панели.
- **Остальные вкладки** — прежняя схема `sceneStyle.paddingBottom`, но
  значение теперь вычисляется, а не захардкожено.

Проверено живьём при полной прокрутке: зазор между нижним краем последней
карточки и верхом панели — ровно 16 px.

## 6b. Устранена дата-зависимая нестабильность `dashboard_import_rehydration`

**Источник:** данные теста, не таймзона и не системное время реализации.
Фикстуры были прибиты к месяцу, в котором файл писался
(`SYNTHETIC_SESSION.date = "2026-07-10"`, `SYNTHETIC_RECORD` = 2026-03),
а проверяемое утверждение — `expect(texts).not.toContain("0 ч")` — говорит
про заголовок карточки цели, который равен
`hoursForMonth(records, now, sessions)`, т.е. **текущему** месяцу. Сессия в
любом другом месяце в этот заголовок не попадает, заголовок остаётся
`0 ч`, тест падает. Тест проходил только пока часы машины были внутри
июля 2026.

Таймзона исключена: путь агрегации `parseISOYearMonth() → sessionsForMonth()`
разбирает ISO-день строкой и вообще не конструирует `Date`.

**Исправление (минимальное, без ослабления проверки):** даты фикстур
выводятся из `new Date()` — сессия попадает в текущий месяц, событие и
legacy-запись — строго в прошлое (6 месяцев назад; legacy-запись за текущий
месяц запрещена `legacyEntryBlockReason()`). Реализация не менялась.

Проверка усилена, а не ослаблена:

- `expect(texts).not.toContain("0 ч")` сохранено дословно;
- добавлено более сильное `expect(texts).toContain("1 ч 30 м")` — заголовок
  равен именно импортированным 90 минутам, а не «чему-то ненулевому»;
- добавлен блок `describe("test fixtures are anchored to the current date")`,
  который падает с внятной причиной, если кто-то снова впишет литеральную
  дату.

**Верификация:** временный `--setupFilesAfterEnv` с
`jest.setSystemTime()` (в репозиторий не попал, удалён) прогнал файл на
датах 2026-01-31, 2026-02-28, 2026-03-01, 2026-07-10, 2026-08-20,
2026-09-01, 2026-12-31, 2027-05-15 — **везде 5/5**. Тот же прогон на
прежней версии файла: зелено только 2026-07-10, на 2026-06-15 и
2026-08-20 — 1 failed. Причина подтверждена экспериментально.
