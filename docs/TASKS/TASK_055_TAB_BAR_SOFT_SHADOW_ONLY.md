# TASK_055 — Убрать остаточную «дымку» позади нижней панели

**Статус:** реализовано, проверено (с оговоркой §2 — см. критерии приёмки)
**Область:** только тень плавающей панели (`src/components/TabBar.tsx`,
стиль `bar`) и корневой HTML веб-сборки (`app/+html.tsx`) — фон/высота
`html`/`body`/`#root` как страховка от щели под `position: fixed` панелью
на настоящем iOS Safari (недоступен для локальной проверки в этой среде,
см. §2).
**Не входит:** форма, скругления, белый фон, активное состояние и
центральная кнопка «Добавить» самой `TabBar.tsx` — не трогаются; правки
TASK_054 (`sceneStyle.paddingBottom`, отступы `ScrollView` на каждом
экране) — не трогаются, уже корректны.

---

## 1. Проблема (продолжение TASK_054)

TASK_054 убрал сплошную полосу-«штору» другого цвета позади `TabBar`
(рассинхронизация фона сцены и фона экрана). Владелец сообщает, что на
реальном iPhone-скрине под панелью всё ещё видна **светлая полоса с
остаточным размытием/тенью** у самого нижнего края экрана — то есть
следующий, более тонкий артефакт, ставший заметным именно после того, как
более грубая проблема TASK_054 была устранена.

## 2. Причина и ограничение среды проверки

Два независимых источника, оба правдоподобны и не исключают друг друга:

1. **Тень самого `bar`** (`src/components/TabBar.tsx`): `shadowOpacity:
   0.12, shadowRadius: 16, shadowOffset: {0, 6}`. Blur-радиус 16 + offset
   вниз 6 на плашке шириной ~318px (при экране 375px, `marginHorizontal:
   20`) визуально растягивает мягкий хвост тени почти на всю ширину
   экрана и смещает его вниз — к самому нижнему краю, ровно туда, где
   владелец видит полосу. Это **не** "родительский слой" — это тень
   самой панели, но она недостаточно "очень мягкая" (`очень мягкая
   тень`, как требует владелец), чтобы не читаться как самостоятельная
   широкая дымка.
2. **`position: fixed` + `viewport-fit=cover` на настоящем iOS Safari**
   (веб/PWA-сборка, `app/+html.tsx`): `html`/`body`/`#root` не имеют
   явного `background-color` (наследуют белый холст браузера). Известный
   класс бага iOS Safari — динамическая высота (`100vh`/`100%` не равна
   фактической высоте видимой области при скрытии/появлении адресной
   строки) может оставить долю пикселя незакрашенной под
   `position: fixed`-элементом, где просвечивает белый холст браузера,
   усиливая визуальный эффект "полосы" рядом с мягкой тенью панели.

**Ограничение:** в этой среде нет полноценного Xcode
(`mcp__Claude_Code_iOS_Simulator__control` → `attach` вернул ошибку "needs
a full Xcode install"), поэтому пункт 2 нельзя ни воспроизвести, ни
провизуально перепроверить на настоящем Mobile Safari — только в
Chromium-based Browser pane, где артефакт не воспроизводится вовсе (см.
TASK_054 §5, тот же инструмент). Правки по пункту 2 — защитные
best-practice меры для этого известного класса бага, не подтверждённые
локально; открыто сообщено владельцу в ответе.

## 3. Решение

1. `src/components/TabBar.tsx`, стиль `bar` — тень уменьшена до
   действительно "очень мягкой": `shadowOpacity: 0.12 → 0.06`,
   `shadowRadius: 16 → 6`, `shadowOffset.height: 6 → 2`. Форма, `elevation`
   (Android), `backgroundColor`, `borderRadius`, `borderWidth`,
   `borderColor` — не менялись. Тень остаётся видимой строго вокруг самой
   плашки, не растягиваясь широким хвостом к нижнему краю экрана.
2. `src/components/TabBar.tsx`, стиль `wrap` — явный
   `backgroundColor: "transparent"` (было — просто отсутствие свойства,
   тот же визуальный результат) с комментарием, фиксирующим требование
   владельца: этот полноширинный контейнер не должен получать фон/тень/
   blur ни при каком будущем изменении.
3. `app/+html.tsx` — добавлен `background-color` (`#f8fafc`, тот же тон,
   что уже служит фоном-заглушкой `SafeAreaView` в
   `app/(tabs)/_layout.tsx`) на `html, body, #root`, и `height: 100dvh`
   (мягкий апгрейд, без `@supports` — на браузерах без поддержки `dvh`
   само объявление отбрасывается парсером, действует прежнее `height:
   100%` из `ScrollViewStyleReset`). Защита от «белого» просвета на
   настоящем iOS Safari — см. §2, п.2.

## 4. Верификация

- `npx tsc --noEmit` — чисто.
- `npx jest` — **964/964, 0 failed** (66/66 suites, без изменений).
- Живая проверка — dev-сервер (`expo start --web`, порт 8082), мобильный
  viewport 375×812, `localhost:8082`, все четыре вкладки (Главная, Часы,
  События, Профиль):
  - Вычисленный `box-shadow` плашки бара —
    `rgba(15, 23, 42, 0.06) 0px 2px 6px 0px` (было `0.12 / 16px / offset
    6px`) — подтверждено через `getComputedStyle()`.
  - Визуально — под панелью и вокруг неё нет широкой полосы/дымки на всех
    четырёх вкладках; тень читается только как мягкий контур вокруг самой
    плашки.
  - Новая вкладка (без унаследованного HMR-состояния) — консоль без ошибок.
  - `getComputedStyle(html/body/#root).backgroundColor` →
    `rgb(248, 250, 252)` (`#f8fafc`) — новый `<style
    id="ministry-ios-safari-viewport-fallback">` применяется, контент
    подтверждён совпадающим с исходником.
- **Не проверено (ограничение среды, см. §2):** реальный iOS Safari —
  ни через `mcp__Claude_Code_iOS_Simulator__control` (нет полноценного
  Xcode), ни каким-либо другим способом в этой сессии. Правка `+html.tsx`
  — защитная мера по известному классу бага, не подтверждённая визуально
  на настоящем устройстве. Владелец должен перепроверить на реальном
  iPhone после деплоя.

## 5. Критерии приёмки

- Тень `TabBar` остаётся видимой, но явно мягче и компактнее — не читается
  как отдельная широкая полоса у нижнего края.
- `wrap` (полноширинный контейнер бара) и `SafeAreaView`/сцена
  `_layout.tsx` — по-прежнему без собственного фона/тени/blur
  (переподтверждено после правки).
- Нижний safe-area остаётся прозрачным — фон текущего экрана виден сквозь
  него, отдельной подложки нет.
- Последняя карточка на каждой из вкладок (Главная/Часы/События/Профиль)
  по-прежнему полностью прокручивается выше панели.
- `npx tsc --noEmit` и `npx jest` — чисто.
- Живая проверка в Browser pane (единственная доступная среда) — визуально
  чисто; ограничение по реальному iOS Safari явно задокументировано в §2 и
  сообщено владельцу.
