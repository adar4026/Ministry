# TASK_029 — Кольцо прогресса: возврат к динамическому заполнению с цветами красный→синий→зелёный

**Статус:** РЕАЛИЗОВАНА, верифицирована локально. Коммит/push/деплой —
ожидают отдельного подтверждения владельца.
**Основание:** ADR-004 (нет TASK — нет кода). Прямая правка владельца после
проверки TASK_028 в проде.
**Связана с:** [[TASK_028]] — эта задача заменяет ключевое архитектурное
решение TASK_028 (кольцо как фиксированная декорация, не зависящая от
`pct`) на основании прямой обратной связи владельца, полученной уже после
деплоя TASK_028.

---

## 1. Запрос владельца (уточнение после TASK_028)

Владелец указал, что интерпретация TASK_028 была неверной: кольцо должно
**расти по мере внесения часов** (т.е. оставаться функциональным
индикатором прогресса, как до TASK_028), а не быть статичной декорацией
с фиксированными зелёным/синим/красным сегментами. Требуемое поведение
цвета по мере роста `pct`:

- в начале (низкий процент) — красный;
- около 50% — синий;
- к завершению цели — зелёный, символизируя выполнение нормы;
- переход в зелёный начинается примерно с 40 часов из цели в 50 часов —
  т.е. около 80%.

Владелец подтвердил: «так все корректно по масштабу» — размер кольца,
толщина обводки, компоновка карточки, блок метрик (TASK_028, часть 2) —
без изменений, правка касается только цветовой/динамической логики
кольца.

## 2. Что меняется относительно TASK_028

`HeroProgressRing.tsx`:

- Убрана фиксированная декоративная раскладка `SEGMENTS`/`GAP_DEG`/
  `GREEN_DEG`/`BLUE_DEG`/`RED_DEG`/`SEGMENT_COLOR` (три независимых дуги
  с зазорами, не зависящие от `pct`) — это и было ошибочным
  архитектурным решением TASK_028.
- Возвращена единая растущая дуга (как до TASK_028):
  `dash = (clamped / 100) * circumference`, один `<Circle>` с
  `strokeLinecap="round"`, `rotation={-90}` (старт сверху), guard
  `dash > 0` (не рисовать при 0%, чтобы закруглённый конец не оставлял
  одиночную точку — тот же приём, что и в `GoalRing.tsx`/до TASK_028).
- Новая функция `colorForPct()` — кусочно-линейная интерполяция по трём
  точкам вместо прежних двух (TASK_028/добавлял: было amber→accent 0–50%,
  accent→green 50–100%; TASK_015/016 — тот же принцип с другими цветами):
  - `0–50%`: красный (`DS.danger`) → синий (`DS.accent`);
  - `50–80%`: синий (`DS.accent`) → зелёный (`DS.green`);
  - `80–100%+`: зафиксировано на зелёном (`DS.green`) — цель «уже на
    завершении зелёный» и «начинает зеленеть примерно с 40 часов»
    (40/50 = 80% от текущей цели `MONTHLY_GOAL`) выражена в процентах, а
    не в абсолютных часах — остаётся корректной независимо от конкретного
    значения `MONTHLY_GOAL`, если оно изменится.
  - Цвета — те же три токена, что уже использовались в decorative-версии
    TASK_028 (`DS.danger`/`DS.accent`/`DS.green`), новых токенов не
    вводилось.
- Светло-серый фоновый круг (`DS.ringTrack`) — без изменений.
- Текст процента в центре (масштаб шрифта по числу цифр, защита от
  `NaN`/`Infinity`/отрицательных значений, несжатый процент при
  перевыполнении цели) — без изменений.
- Пропсы (`pct`, `size`) — без изменений; `HoursHeroCard.tsx` не
  потребовал правок вызова.

Блок метрик «Осталось / До конца» (TASK_028, часть 2) — **не трогается**,
остаётся в текущем виде (две равные колонки, подпись «До конца»,
центрированный разделитель).

## 3. Не трогаем

- Размер кольца (`size=48`), толщина обводки (`size * 0.19`).
- Логика текста процента и его масштабирования.
- Блок метрик, полоса прогресса, текст опережения/отставания, кнопки
  «Детали»/«Добавить», расчёты `monthProgress()`/`MONTHLY_GOAL`.
- Другие страницы — компонент по-прежнему используется только в
  `HoursHeroCard.tsx` → только Главная (без изменений в области
  использования относительно TASK_028).
- `GoalRing.tsx` — не трогается.

## 4. Тесты

Добавлен тест на цвет обводки при характерных `pct` (0/50/80/100) —
раньше цветовая логика кольца не покрывалась тестами ни в TASK_015/016
(старая `colorForPct`), ни в TASK_028 (фиксированные сегменты); теперь,
после второго изменения того же поведения, добавлено регресс-покрытие,
чтобы будущая правка не тихо сломала контрольные точки без замечания.

## 5. Architecture Review Checklist (ADR-007)

- Нет нового бэкенда, миграции схемы хранения, аутентификации.
- Чисто презентационное изменение одного компонента; `monthProgress()`/
  `MONTHLY_GOAL`/`StoreContext` не затронуты.
- Версия (`0.4.4`) и последний тег — не менялись.

## 6. Проверки (обязательны перед коммитом)

- `npx tsc --noEmit`
- `npx jest`
- `npx expo export --platform web`
- Визуальная проверка dev-сервера на 320/375/428px при нескольких
  значениях `pct` (низкое/около 50%/около 80%/100%+): дуга растёт вместе
  с процентом, цвет проходит красный→синий→зелёный по описанным точкам,
  закруглённый конец дуги, отсутствие деформации на всех трёх ширинах.

## 7. Результат

Проверки: `npx tsc --noEmit` — чисто; `npx jest` — **400/400**, 31 сьют
(было 396/396 — +4 новых теста на цвет дуги при 0/25/50/65/80/100/130%);
`expo export --platform web` — успешно, 24 статических маршрута (без
изменений). Визуальная проверка (dev-сервер, временные тестовые сессии
этой сессии на 5/25/32.5/42 часа — 10%/50%/65%/84% от цели в 50 часов, без
записи в данные владельца) на 320×700, 375×700, 428×700: на 10% — дуга
красная (маленькая); на 50% — дуга ровно синяя; на 65% — переходный
сине-зелёный (между точками 50% и 80%); на 84% (42 из 50 часов) — дуга
полностью зелёная, что подтверждает требуемый переход «примерно с 40
часов»; дуга растёт вместе с процентом на всех проверенных значениях;
закруглённый конец дуги; кольцо не деформируется ни на одной из трёх
ширин; `document.documentElement.scrollWidth === window.innerWidth`;
консольных ошибок нет (только предсуществующее SVG-предупреждение
`transform-origin`, см. TASK_017/023/028).

Коммит/push/деплой — **не выполнялись**, ожидают отдельного подтверждения
владельца.
