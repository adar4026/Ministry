# TASK_011 — Hours Entry Redesign: iOS-style Hour/Minute Wheel Picker

**Статус:** РЕАЛИЗОВАНА и независимо одобрена (Opus, `APPROVED WITH
NON-BLOCKING NOTES`) после двух раундов исправлений — см. §5, §8. Статус
релиза (commit/push/deploy/production) фиксируется в `docs/STATUS.md`.

**История ревью:**
1. Первое независимое ревью (Opus) вернуло `CHANGES REQUIRED` — блокер:
   легаси-длительности, не кратные 5 минутам (например, 47 мин), при
   редактировании только одного колеса тихо теряли точность (отображали
   округлённое значение, но сохраняли отдельно хранимое "точное").
2. Первое исправление заменило это на инжекцию точного легаси-остатка как
   дополнительного пункта колеса минут (47 отображалось и сохранялось как
   47). **Владелец явно отклонил это решение**: колесо минут должно
   содержать **только** стандартные значения `0, 5, 10, …, 55` — никаких
   произвольных пунктов вроде 47/22/38 ни при каких обстоятельствах.
3. Финальное, владельцем одобренное решение (см. §5): легаси-остаток
   **округляется** до ближайшего кратного 5 при открытии записи на
   редактирование (обычное округление: остаток 0–2 вниз, 3–4 вверх, с
   переносом через час), а пользователю показывается краткое
   информационное сообщение о том, что время было округлено. Отображаемое
   и сохранённое значение всегда совпадают — без инжекции произвольных
   значений в барабан.
4. Повторное независимое ревью (Opus) финальной версии — `APPROVED WITH
   NON-BLOCKING NOTES` (все обязательные проверки PASS; несблокирующие
   замечания: клампинг >24ч недостижим в предметной области и не создаёт
   расхождения отображаемого/сохранённого значения; косметический отступ
   у сообщения об округлении на узких экранах; предсуществующее
   SVG-предупреждение react-native-web, не связанное с TASK_011).
**Основание:** ADR-004 (нет TASK — нет кода). Владелец описал и одобрил
продуктовое и UX-решение (референс-скриншот приложен), включая явную
границу: без изменений схемы хранения, без релизных операций.

---

## 1. Цель

Заменить ручной ввод длительности (текстовое поле "минуты") на
`/hours/entry` двумя независимо прокручиваемыми колёсами в стиле iOS —
часы и минуты — и переоформить экран под референс-композицию (компактная
шапка "Отмена/Добавить", карточка "Дата", карточка "Время" с колёсами,
карточка "Заметка").

## 2. Область изменений

- `app/(tabs)/hours/entry.tsx` — шапка (Отмена / заголовок / Добавить или
  Сохранить), общая компоновка карточек.
- `src/components/forms/SessionForm.tsx` — состояние часы/минуты вместо
  текстового поля минут; сохранение через существующий `saveSession()` /
  `SessionInput` без изменений контракта; легаси-длительности округляются
  через `roundDurationToNearestFive()` при монтировании (см. §5).
- `src/data/constants.ts` — `roundDurationToNearestFive()` — чистый
  хелпер округления до ближайших 5 минут, с тестами
  (`src/data/__tests__/constants.test.ts`).
- Новый переиспользуемый `src/components/WheelPicker.tsx` — колонка
  прокручиваемых значений с центральным хайлайтом и затуханием соседних

- Новый `src/components/forms/DurationWheelPicker.tsx` — композиция двух

- `src/data/constants.ts` — добавлены `formatHoursWord()` /

- Тесты: `SessionForm.test.tsx` переписан под новую структуру;
  добавлены тесты `WheelPicker`/`DurationWheelPicker` при необходимости.

## 3. Обнаруженное архитектурное расхождение (задокументировано, не блокирует)

Референс-скриншот содержит карточку "Fecha" с **двумя** пилюлями — дата и
**время суток**. У `Session` для `source: "manual"` время суток
(`startTime`/`endTime`) архитектурно отсутствует и не требуется — это
явное решение `TASK_005_ARCHITECTURE.md` §6 ("manual entry must never
require the user to invent or remember exact start/end times"),
воспроизведённое в комментарии `SessionForm.tsx`. `startTime`/`endTime`
для timer-сессий — необязательные информационные метки, не для ручного
ввода.

Сама задача TASK_011 явно исключает изменение схемы хранения и явно
требует: "Preserve existing date and time functionality. Do not replace
working business logic merely to match the screenshot." Поскольку
функциональности "время суток" для ручного ввода не существует — она не
добавляется. Карточка "Дата" в этой задаче содержит **только** контроль
даты. Решение не требует паузы/уточнения у владельца — оно прямо следует
из процитированной инструкции самой задачи.

## 4. Хедер: Добавить vs Сохранить

Референс — экран создания записи (единый сценарий, без recognizable
edit-режима). Существующий `/hours/entry` поддерживает и создание, и
редактирование с разными заголовками ("Добавить время" /
"Редактировать запись"). Решение: в режиме создания правая кнопка —
"Добавить" (как в референсе); в режиме редактирования — "Сохранить"
(сохраняет существующую семантику приложения, не притягивает
create-формулировку к edit-сценарию). Кнопка удаления (существующий
`Alert.alert`-флоу) сохраняется для edit-режима — не часть референса, но
существующая бизнес-логика, которую задача явно требует не терять.

## 5. Конвертация длительности (финальная, владельцем одобренная версия)

- UI: часы (0–24) + минуты **только** стандартные значения `0, 5, 10, …,
  55` (шаг 5). Никакое другое значение не может появиться как пункт
  колеса минут ни при каких обстоятельствах — ни для новых записей, ни
  при редактировании легаси-записей.
- Загрузка существующей записи: `hours = floor(total / 60)`,
  `minutes = total % 60`. Если `total` не кратен 5 (легаси/таймер-записи:
  `durationMinutes = ceil(bankedSeconds/60)`, редактируемо пользователем,
  либо любая историческая запись), значение **округляется** к ближайшему
  кратному 5 через `roundDurationToNearestFive()`
  (`src/data/constants.ts`) **один раз, при монтировании** экрана
  редактирования, **до** разбиения на часы/минуты — так перенос через час
  обрабатывается корректно одним шагом (например, 58 → 60 → "1 час 0
  минут", а не "0 часов 60 минут").
  - Стандартное округление до ближайших 5: остаток 0–2 — вниз, 3–4 — вверх
    (`Math.round(total / 5) * 5`).
  - Примеры: `47 → 45`; `48 → 50`; `58 → 60` (перенос в час); `107 → 105`
    (1ч45м); `108 → 110` (1ч50м).
- **Никакого скрытого "точного" состояния не существует.** `hours` и
  `minutes` — это единственное состояние формы; `durationMinutes` всегда
  честно вычисляется как `hours * 60 + minutes` из видимых значений колёс.
  Отображаемое и сохранённое значение не могут разойтись — ни для новых,
  ни для округлённых легаси-записей.
- Если запись была округлена при загрузке, под карточкой "Время"
  появляется краткое информационное сообщение: **«Время округлено до
  ближайших 5 минут»** (нейтральный, некритичный стиль — не красный/danger,
  как валидационная ошибка). Сообщение вычисляется один раз из
  `initial.durationMinutes % 5 !== 0` — историческй факт о загруженной
  записи, не зависит от дальнейшего взаимодействия с колёсами. Для новых
  записей и записей, уже кратных 5, сообщение не показывается.
- Раз `hours`/`minutes` — единственное состояние, редактирование только
  заметки/даты автоматически сохраняет округлённое значение неизменным
  (колёса не трогались); редактирование только одного колеса (например,
  выбор "1 час" у округлённой записи 47→45 мин) сохраняет `105`
  (`1*60+45`) — то есть именно то, что видно на экране, а не исходные 47.
- Сохранение: `totalMinutes = hours * 60 + minutes`, всегда, без условий.
- Комбинация `0 часов / 0 минут` не может быть сохранена — кнопка
  Добавить/Сохранить неактивна, под карточкой "Время" — пояснение
  (отдельное от сообщения об округлении).
- **Верхняя граница (защитный клампинг):** колесо часов поддерживает
  только 0–24. Если округлённая длительность соответствует часовой части
  больше 24 (нереалистично для одной записи служения, но теоретически
  возможно), часы клампятся до 24, минуты остаются как вычислено — так
  видимое значение всегда существует как реальный пункт списка. Покрыто
  тестом; не требует изменения схемы хранения.

### 5.1 История подходов (для памяти, оба отклонены/заменены)

1. **Исходная реализация:** показывала на колесе минут округлённое
   значение, но хранила точное исходное в отдельном состоянии до первого
   касания колеса. Независимое ревью (Opus) выявило расхождение
   отображаемого/сохранённого значения и тихую порчу данных при касании
   только одного колеса (47 → выбор "1 час" → сохранялось 105 вместо
   107). Отклонено ревью.
2. **Промежуточное исправление:** инжектировало точный легаси-остаток
   как дополнительный пункт колеса минут (47 отображалось и сохранялось
   как настоящие 47). Технически устраняло расхождение, но **владелец
   явно отклонил** сам продуктовый принцип — колесо минут обязано
   содержать только стандартные значения, без исключений.

Финальная версия (§5 выше) — округление легаси-остатка с явным
информационным сообщением — одобрена владельцем как окончательная.

## 8. Исправления по итогам ревью (два раунда)

**Раунд 1 — блокер (устранён затем заменён владельцем):** первое
исправление инжектировало точный легаси-остаток в список опций колеса
минут. Устраняло расхождение отображаемого/сохранённого значения, но
владелец явно отклонил сам принцип — колесо минут не должно содержать
никаких нестандартных значений.

**Раунд 2 — финальное решение (см. §5):** `legacyMinuteValue` и
инжекция (`buildMinuteItems()` с произвольными значениями) полностью
удалены из `DurationWheelPicker.tsx` — список минут снова статический
`[0,5,…,55]`. Вместо инжекции добавлен чистый хелпер
`roundDurationToNearestFive()` (`src/data/constants.ts`) и
информационное сообщение о округлении в `SessionForm.tsx`. Никакого
скрытого "точного" состояния нет ни в одном из раундов финальной версии.

**Второстепенные улучшения (сохранены из раунда 1, не зависят от
инжекции — оставлены без изменений):**
- `WheelPicker.tsx`: колесо ресинхронизирует позицию скролла, если
  контролируемое значение `value` меняется извне (не через собственный
  `onChange` компонента) — отслеживается через `lastScrolledIndex`, не
  конфликтует с пользовательским drag/momentum (см. комментарии в коде).
- `WheelPicker.tsx`: `accessibilityActions` (increment/decrement) +
  `onAccessibilityAction`, использующие тот же путь выбора
  (`snapToIndex`), с тем же клампингом на границах списка.

**Тесты:** `SessionForm.test.tsx` переписан — тесты, кодировавшие старое
расхождение отображаемого/сохранённого значения, заменены тестами,
проверяющими честное поведение (инициализация 47/107 мин, редактирование
только часов/только заметки/только даты, явный выбор стандартного
значения). `WheelPicker.test.tsx` — добавлены тесты внешней
ресинхронизации значения и accessibility-действий increment/decrement (с
клампингом на границах).
