# TASK_020A — Компактные метки оставшегося времени до предстоящих событий

**Статус:** ЗАВЕРШЕНА — реализована и верифицирована локально.
**Основание:** ADR-004 (нет TASK — нет кода). Запрошено владельцем напрямую.
**Связана с:** [[TASK_020]] (`TASK_020_UPCOMING_EVENTS_PRECISE_REMAINING_TIME.md`)
— эта задача не меняет календарную арифметику TASK_020, только
пользовательский текст, который она формирует.

---

## 1. Проблема

TASK_020 ввела точные календарные метки вида «Через 1 месяц 17 дней»,
«Через 2 месяца 20 дней», «Через 11 месяцев 29 дней». Расчёт корректен,
но полные русские слова делают метку избыточно длинной для компактного
UI списка предстоящих событий (`UpcomingEventRow`).

## 2. Требуемое изменение

Заменить полные слова «месяц(-а/-ев)» / «день/дня/дней» на компактные
сокращения:

- месяцы → `мес` (без склонения, без точки, без учёта числа);
- дни → `д.` (без склонения, с точкой).

## 3. Формат

- «Через 1 мес 17 д.» — полные месяцы + остаток дней;
- «Через 1 мес» / «Через 5 мес» — только полные месяцы, без «0 д.»;
- «Через 1 д.» / «Через 20 д.» — только дни, без полных месяцев;
- «Сегодня» — без изменений (событие сегодняшним днём);
- один пробел между всеми частями; префикс «Через» сохранён;
- никогда не показывается «0 мес», «0 д.» или «Через 0 д.».

## 4. Область изменений

Правится **только** `relativeDays()` в `src/data/constants.ts` — теми же
двумя литералами `мес`/`д.` вместо вызовов `monthWord()`/`dayWord()`.
Календарная арифметика (`addMonthsClamped`, `daysBetweenUTC`, поиск
наибольшего целого числа месяцев) из TASK_020 **не меняется** — дефектов
не найдено, править нечего.

`monthWord()` и `dayWord()` (полное русское склонение) **не удаляются и
не меняются** — они используются другими, не связанными с этой задачей
местами с полным склонением («До конца месяца: 5 дней», «Осталось: N
дней»):

- `src/components/TodayCard.tsx`;
- `src/components/MonthSummaryCard.tsx`;
- `src/components/dashboard/HoursHeroCard.tsx`.

Компактный формат — особенность именно `relativeDays()` (компактный
список предстоящих событий), не общее изменение плюрализации в проекте.

- `src/data/constants.ts` — `relativeDays()`: `monthWord(months)` →
  литерал `"мес"`, `dayWord(days)` → литерал `"д."`.
- `src/data/__tests__/constants.test.ts` — существующие тесты
  `relativeDays` обновлены на компактный вывод; тесты `monthWord`/
  `dayWord` (полное склонение, используются другими компонентами)
  остаются без изменений.

## 5. Вне области (не трогаем)

- `monthWord()`/`dayWord()` — сами функции полного склонения не
  меняются (используются вне `relativeDays()`).
- Календарная арифметика TASK_020 (`addMonthsClamped`,
  `daysBetweenUTC`, поиск месяцев/дней) — без изменений.
- Двухстрочная раскладка `UpcomingEventRow` (заголовок сверху; дата
  слева снизу; срок справа снизу) — не меняется; стили не трогаются,
  если более короткий текст не вскроет реальный дефект вёрстки.
- Вкладка «События» (`/timeline`) — не использует `relativeDays()`,
  не затронута.
- Лимит Главной = 3, кнопка «Показать все», структура
  `/upcoming-events` — без изменений.

## 6. Тесты

`src/data/__tests__/constants.test.ts`, `describe("relativeDays…")` —
существующие кейсы TASK_020 обновлены на компактный формат:

- месяцы + дни;
- ровное число месяцев (без «0 д.»);
- только дни;
- 1 месяц / несколько месяцев;
- 1 день / несколько дней;
- «Сегодня»;
- отсутствие нулевых единиц;
- переход через конец года и клампинг конца месяца (календарная
  арифметика TASK_020) — поведение подтверждено неизменным, только
  текст вывода обновлён под новый формат.

## 7. Проверки

- `npx tsc --noEmit` — чисто; `npx jest` — 28 сьютов, 359 тестов (без
  изменения количества — только обновлены ожидаемые строки);
  `npx expo export --platform web` — успешно, 24 статических маршрута.
- Визуальная проверка (dev-сервер, временные тестовые события, без
  записи в данные владельца) Главной («Ближайшие события») и
  `/upcoming-events` на 375×812 и 320×568 (узкий): компактные строки
  («Через 2 мес 20 д.», «Через 11 мес 29 д.») теперь помещаются в одну
  строку даже на 320px — перенос строки, введённый в TASK_020 для
  длинных полных формулировок, на компактном формате уже не
  срабатывает. Реального дефекта вёрстки не найдено — правка стилей
  не потребовалась.
