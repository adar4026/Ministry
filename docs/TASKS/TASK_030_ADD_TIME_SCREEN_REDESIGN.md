# TASK_030 — Редизайн экрана «Добавить время» (Apple/iOS)

**Дата:** Июль 2026
**Статус:** В работе

## 1. Запрос владельца

Полный редизайн `app/(tabs)/hours/entry.tsx` (+ `SessionForm.tsx`) в стиле
Apple/iOS: холодный серый фон экрана, белые карточки, capsule-кнопки
Отмена/Добавить, крупный заголовок, дата только как pill (без времени
суток) с открытием полноценного календаря месяца на русском (с
понедельника), сохранённый wheel picker часов/минут (уже существует,
TASK_011) — restyle цветов, удаление красного validation-текста,
компактное поле заметки. Оригинальный промпт владельца (полный, на
русском) сохранён в истории сессии; здесь фиксируется техническая
интерпретация и конкретные решения.

- `SessionForm.tsx` — тело формы (`Card`/`TextField`/`DangerButton`/

  `DS`-токены Главной).
- **Duration wheel picker уже существует** и уже реализует большую часть

  accessibility increment/decrement) + `src/components/forms/
  DurationWheelPicker.tsx` (часы 0–24, минуты 0/5…55). Требуется только
  **restyle** (цвет highlight-строки), не переписывание.
- **Русское склонение часов/минут уже существует**: `formatHoursWord`/
  `formatMinutesWord` в `src/data/constants.ts` (не дублировать).
- **Модель данных не меняется**: `Session.durationMinutes` + `Session.date`
  (ISO-день); `startTime`/`endTime` уже опциональны и используются только

  `styles.hint` (цвет `COLORS.danger`).
- **Save flow** — `SessionForm.submit()` → `onSave` (в `entry.tsx`) →
  `saveSession()` (`StoreContext`) → `router.back()`. Обновление Главной —
  чистая реактивность `useStore()` контекста, без ручного refetch;
  `HoursHeroCard`/`HeroProgressRing` (TASK_028/029) не трогаются и не
  требуют правок.
- **Токены цвета из ТЗ отсутствуют** — `screenBackground #EBEBEF`,
  `cardBackground #FFFFFF` (именованный), `selectedPickerRow #E8E8EA`,
  `datePillBackground #E3E3E5` нигде не определены; ближайший аналог —
  `COLORS.groupedBg #f2f2f7` (используется сейчас и в date pill, и в
  wheel highlight).
- **Зависимости**: `expo-haptics` не установлен → haptics не добавляются
  (не заводить зависимость без необходимости). Библиотек календаря нет →
  month grid реализуется как чистая функция + локальный компонент.

  заголовком/крестиком) существует, но его шапка (title + ✕) не подходит
  визуально референсу календаря (месяц/год + ‹ › без отдельной title-бар);

  centered sheet), но новый компонент, не обёртка над общим `Modal`.
- Полные русские названия месяцев уже существуют — `MF` в

  переиспользуются для заголовка календаря. Короткие дни недели
  (Пн…Вс) нужно завести — их нигде нет.

## 4. Технические решения (там, где ТЗ оставляло выбор)

1. **Токены цвета** — новый локальный файл `src/components/forms/
   entryTokens.ts` (по аналогии с `src/components/dashboard/tokens.ts`
   для Главной) — не расширяет глобальный `COLORS`, чтобы не задеть другие
   экраны, использующие `COLORS.bg`/`COLORS.groupedBg`.
2. **Поле даты становится нажимаемым pill без свободного ввода** — прямое
   следствие ТЗ §8 («вся pill является нажимаемой», «нажатие открывает
   календарь», клавиатурный текстовый ввод даты в референсе отсутствует).
   Это меняет текущее поведение (сейчас можно вписать любую дату
   вручную) — фиксирую явно как содержательное изменение, а не просто
   стилизацию. Внутреннее состояние формы переходит с DD-MM-YYYY строки
   на ISO-строку напрямую (упрощает — выбор из календаря всегда валиден,
   `isValidDMY`/`parseDMYToISO` для этого экрана больше не нужны;
   `formatDateDMY` остаётся — для отображения в pill).
3. **Ограничений на даты не вводится** — сейчас их нет (свободный текст
   принимал любую дату), календарь должен разрешать любой месяц/год без
   ограничений сверху/снизу, только через ‹ Пред / След ›, без быстрого
   перехода по году (ТЗ описывает только стрелки месяца — литерально
   следую спецификации, не добавляя лишнего UI).
4. **Цвет выбранного дня** — переиспользуется существующий `COLORS.accent`
   (`#3b82f6`), как явно предписано ТЗ §9.5 («сначала используй
   существующий accent, если подходит»); финальная проверка — визуально,
   на скриншоте.
5. **Пустые ячейки** для дней соседних месяцев (не приглушённые числа) —
   так же, как на референс-скриншоте владельца (пустая первая строка
   до 19 июля).
6. **KeyboardAvoidingView** — в проекте такого паттерна нигде нет; добавляется
   локально только в `entry.tsx` (behavior `padding` на iOS, `undefined`
   на Android/web — RN default), чтобы клавиатура не перекрывала «Заметку».
7. **`SectionTitle`/`Card`/`TextField` из `ui.tsx` не меняются** — это
   общие компоненты (используются `RecordForm`/`EventForm`/`TalkForm` и
   другими экранами); экран получает нужный вид через `style`-пропы на
   `Card` (уже так и было устроено — `dateCard`/`durationCard`/`noteCard`)
   и через собственные локальные заголовки-секции вместо `SectionTitle`,
   где нужна более крупная типографика.
8. **`?date=` параметр** в `month/[key].tsx` (строка 175) сейчас не
   читается `entry.tsx` (мёртвая проводка, найдено при исследовании) —
   вне области этой задачи, не трогается и не чинится здесь.

## 6. Architecture Review Checklist (ADR-007)

- Нет нового бэкенда, миграции схемы хранения, аутентификации — `Session`
  не менялся; мануальный ввод по-прежнему никогда не пишет `startTime`/
  `endTime`.
- Новые токены (`entryTokens.ts`) и новый чистый модуль (`calendarGrid.ts`)
  — локальны для этого экрана, не расширяют глобальный `COLORS`/`DS`.
- Общие компоненты (`Card`/`TextField`/`DangerButton`/`Modal` в `ui.tsx`/
  `Modal.tsx`) не изменены — новый экран получает нужный вид через
  `style`-пропы и новый отдельный `MonthCalendarModal`, не правкой общих
  default-стилей.
- `WheelPicker.tsx` получил один новый необязательный проп
  (`highlightColor`, по умолчанию — прежнее поведение) — обратно
  совместимо, других мест использования нет (`grep` подтвердил).
- Версия (`0.4.4`) и последний тег — не менялись.
- **Обнаруженная, не исправляемая в этой задаче гонка (вне области):**
  если `EntryScreen` в режиме редактирования монтируется до завершения
  асинхронной гидратации `StoreContext` из `AsyncStorage`, `SessionForm`
  успевает смонтироваться с `initial === undefined` и его wheel-`useState`
  инициализируется нулями безвозвратно (React не перезапускает
  initializer при последующем изменении пропа). В реальной навигации это
  не проявляется — `?id=` открывается только с экрана (история/детали
  месяца), который уже показывает список сессий, то есть `sessions` уже
  гидратированы к моменту перехода; баг существовал и до TASK_030
  (тот же паттерн `useState(initialWheelState(...))` был и в старой
  версии `SessionForm`). Обнаружено при написании
  `app/__tests__/entryScreen.test.tsx` — тест переписан так, чтобы не
  наступать на эту гонку (сессия гидратируется в отдельной фазе до
  монтирования `EntryScreen`), сама гонка не устранена.
- **Добавлен guard от двойного сохранения** (`entry.tsx`,
  `submittedRef`) — при редизайне обнаружилось, что `SessionForm.submit()`
  не имел защиты от повторного вызова (только проверку `canSubmit`);
  быстрый двойной тап создавал бы две записи. Исправлено `useRef`-флагом
  в `entry.tsx`, не в `SessionForm` (форма остаётся презентационной).
