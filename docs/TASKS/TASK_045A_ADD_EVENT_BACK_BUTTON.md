## Проблема

Экран `/add?focus=event` (открывается со страницы «События» через «＋
Добавить событие», TASK_045 §2) не имеет понятного способа отменить
создание события и вернуться назад — ни явной кнопки, ни визуальной
подсказки. Единственный выход — системный жест/кнопка возврата ОС.

## Цель

Добавить в верхней части этого экрана единую круглую кнопку «Назад»
(`src/components/BackButton.tsx`, тот же компонент, что уже используют
`hours/timer.tsx`, `hours/history.tsx`, `upcoming-events.tsx` — TASK_037
§6). Никакой новой/локальной копии кнопки.

## Область изменения

- `app/(tabs)/add.tsx` — кнопка рендерится **только** когда `focus ===
  "event"` (`eventOnly`); это единственный вход, описанный в задаче. Путь
  без параметра (через таб-бар «+», все три карточки) не меняется — там
  кнопки нет, как и раньше.
- `src/components/BackButton.tsx` — новый необязательный проп
  `alwaysReplace` (см. «Находка по ходу реализации» ниже). По умолчанию
  `false` — поведение для всех существующих потребителей (`timer.tsx`,
  `history.tsx`, `upcoming-events.tsx`) не меняется.

## Находка по ходу реализации — `canGoBack()`/`back()` возвращали не туда

Первая версия использовала `BackButton` без изменений
(`fallbackHref="/timeline"`, штатная логика `canGoBack() ? back() :
replace(fallbackHref)`). Предположение — как и во всех прежних
потребителях `BackButton` — было, что `canGoBack()` истинно ровно тогда,
когда есть корректная запись «Мероприятия» для возврата.

Визуальная проверка в браузере (реальный, не синтетический клик: запуск
приложения → вкладка «Мероприятия» → «Добавить событие» → «Назад»)
показала расхождение: кнопка возвращала на **Главную**, а не на
«Мероприятия».

Причина — архитектурное отличие этого экрана от всех прежних
потребителей `BackButton`. `history.tsx`/`timer.tsx` вложены в
собственный `Stack` (`hours/_layout.tsx`); `upcoming-events.tsx` — вне
`(tabs)`, отдельный экран корневого `Stack`. У всех у них «предыдущая
запись истории» гарантированно корректна. `add.tsx` — не так: это
**соседний** `Tabs.Screen` для `timeline.tsx` (оба объявлены в одном
`Tabs` внутри `app/(tabs)/_layout.tsx`), а переключение вкладки через
таб-бар (`TabBar.tsx`, `navigation.navigate(routeName)`) вообще не
добавляет запись в историю — URL меняется, но новой «точки возврата» не
создаётся. Когда `timeline.tsx` затем вызывает `router.push("/add?
focus=event")`, добавляется ровно одна запись поверх того, что было
открыто **до** переключения на вкладку «Мероприятия» — то есть чаще всего
Главной. `canGoBack()` при этом истинно, а `back()` уводит мимо
«Мероприятия».

### Исправление

`BackButton` получил новый необязательный проп `alwaysReplace` — если
`true`, кнопка всегда делает `router.replace(fallbackHref)`, минуя
`canGoBack()`/`back()` целиком. `app/(tabs)/add.tsx` передаёт его для
кнопки в режиме `eventOnly`:

```tsx
<BackButton fallbackHref="/timeline" alwaysReplace />
```

По умолчанию (`alwaysReplace` не указан) поведение всех остальных
потребителей `BackButton` не меняется — они не задеты этой проблемой
(собственный `Stack` или отдельный корневой экран), поэтому правка
аддитивна и не требует их правки/повторной проверки их сценариев (кроме
прогона общего Jest, см. «Проверки»).

Повторная визуальная проверка (тот же реальный сценарий: Главная → таб
«Мероприятия» → «Добавить событие» → ввод незаконченного названия →
«Назад») подтвердила: возврат теперь корректно приходит на
«Мероприятия», незаконченное событие не появляется ни в списке, ни в
`AsyncStorage`/`localStorage` (`mj_events_v1`).

## Расположение

Слева сверху, над карточкой формы — тот же паттерн заголовка, что в
`upcoming-events.tsx`/`hours/history.tsx`. Отступ от status bar не
требует собственного `SafeAreaView` на этом экране — `add.tsx`
рендерится как таб верхнего уровня внутри `app/(tabs)/_layout.tsx`,
который уже оборачивает всю `Tabs`-навигацию в `SafeAreaView` с
`edges:["top","left","right"]`; второй вложенный `SafeAreaView` здесь не
нужен и не добавлен (в отличие от `hours/timer.tsx`/`hours/history.tsx`
— те вложены в свой `Stack`, вне внешнего safe-area отступа, поэтому там
`SafeAreaView` обязателен; `add.tsx` — прямой `Tabs.Screen`, как
`timeline.tsx`/`profile.tsx`, у которых по той же причине нет своего
`SafeAreaView`).

Заголовок-текст рядом с кнопкой не добавлен — не требуется заданием, и в
режиме `focus=event` уже есть заголовок карточки «Добавить событие»
ниже.
