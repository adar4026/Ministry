### Какие данные реально доступны (проверка достоверности, п. 3 задания)

Проверены `src/types/index.ts` и `src/data/stats.ts`:

- **`Session`** — `date: "YYYY-MM-DD"` + `durationMinutes`. **Реальная дата
  каждого внесения часов есть.** Это авторитетный источник с TASK_005.
- **`HourRecord`** (легаси) — только `{ year, month, hours, creditHours? }`.
  **Дневной даты нет вообще**: это итог за месяц.
- Разрешение факта — `resolveMonthTotal()` (`src/data/stats.ts`):
  если за месяц есть хотя бы одна `Session` — итог считается по сессиям и
  легаси-запись за этот месяц **игнорируется полностью**; иначе берётся
  `HourRecord.hours`. Это единственное место такой резолюции — новые
  графики строятся поверх него, поэтому двойного учёта часов возникнуть
  не может.

**Вывод:** дневную накопительную линию честно можно строить только по
`Session`. Искусственно «размазывать» месячный итог легаси-записи по дням
запрещено заданием и не делается. Фолбэк:

- **Экран месяца** без сессий (только легаси-итог) — фактическая линия не
  рисуется вовсе; вместо неё явная надпись, что за этот месяц сохранён
  только месячный итог без разбивки по дням.
- **Экран служебного года** — линия непрерывна, но месяц без дневной
  детализации добавляется **одним шагом в последний день этого месяца**
  (накопленный итог на конец месяца — факт, известный точно; неизвестна
  только форма внутри месяца), и под графиком выводится примечание с
  перечнем таких месяцев. Никакой миграции и изменения схемы данных не
  требуется — старые данные не трогаются.

### Как устроены данные графика

- Факт месяца: `dailyMinutesForMonth()` → дельта по каждому дню → накопление
  с 1-го числа до `lastActualIndex` (сегодня для текущего месяца, последний
  день — для прошедшего, ничего — для будущего).
- Факт года: посуточные дельты по всем месяцам служебного года; месяц с
  сессиями считается по сессиям (легаси-запись за него игнорируется целиком,
  как в `resolveMonthTotal()` — двойного учёта нет), месяц без сессий входит
  одним шагом в свой последний день и попадает в `approximateMonths`.
- Идеальный темп: `idealHoursAt()` → уже существующая
  `idealCumulativeHours()`; прямая 0 → цель на длину периода. Не прогноз:
  от факта не зависит и всегда кончается на исходной цели, даже если факт
  её превысил.
- Шкала Y: `niceScale(max(цель, факт))` — 0…50 по 10 для месяца, 0…600 по
  100 для года; при превышении цели верх шкалы растёт, пунктир идеального
  темпа остаётся на цели.
- Конец фактической линии по построению равен `doneHours` карточки —
  закреплено тестом «цифра и график не расходятся».

### Ограничения для старой истории

Дневная линия существует только там, где есть `Session` с реальной датой.
Для `HourRecord` (только месячный итог) поведение описано выше: экран месяца
показывает надпись вместо линии, экран года — шаг в последний день месяца
плюс явное примечание со списком таких месяцев. Данные не мигрировались,
схема не менялась, ключи хранилища не менялись, старые записи не
переписывались.
