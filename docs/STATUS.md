### Архитектура и модель данных

- Expo + React Native (expo-router, TypeScript), Expo SDK 54.
- Единый `StoreContext` — вся работа с данными идёт только через него.
- **Session-first агрегация (TASK_005A):** для каждого месяца
  авторитетный источник ровно один — `Session`, если для месяца есть хотя
  бы одна запись, иначе легаси `HourRecord`. Источники никогда не
  смешиваются. Реализовано в `src/data/constants.ts`:
  `monthTotal()`, `sessionsForMonth()`, `serviceYearAggregation()`;
  `hoursForMonth()` / `monthProgress()` / `groupBySY()` обновлены
  внутренне (тот же контракт, тот же результат на легаси-данных).
- **Главная (Home) — Session-aware ViewModel:** `index.tsx` не
  агрегирует `HourRecord` напрямую — использует `serviceYearAggregation()`
  и ViewModel `ServiceYearMonth` (`{ id, year, month, hours, source }`)
  для сетки текущего служебного года. Логика и данные Главной не менялись
  ни в TASK_005A, ни в TASK_006 (последний — чисто визуальная полировка).
- **Правило блокировки легаси-записи (TASK_005B, «блокируется, а не
  предупреждает»):** легаси-форма `RecordForm` (используется в
  `add.tsx`, `hours.tsx` и Главной) отказывается сохранять для: текущего
  календарного месяца, любого будущего месяца, и любого прошлого месяца,
  где уже есть ≥1 `Session`. Прошлые месяцы без сессий остаются
  полностью редактируемыми (легитимный сценарий ретроспективного
  заполнения истории). Единая точка проверки —
  `legacyEntryBlockReason()` в `src/data/constants.ts`; ни один экран не
  дублирует эту проверку самостоятельно. При блокировке форма показывает
  явное пояснение внутри себя, а не тихо отказывает и не просто
  предупреждает.
- Экран **Часы** (`hours.tsx`) и **TodayCard** используют те же функции
  (`groupBySY`, `hoursForMonth`, `monthProgress`), теперь Session-aware:
  `TodayCard` уже передаёт `sessions`, `hours.tsx` продолжает вызывать их
  без `sessions` — его редизайн запланирован на TASK_005D.
