### TASK_013 — Резервная копия данных: экспорт/импорт (Safari → PWA) — задеплоена, проверена в проде (UI), физическая проверка на iPhone ожидается

- **Проблема:** на iOS Safari и установленное на экран «Домой» PWA-приложение
  Ministry используют раздельные контейнеры локального хранилища —
  свежеустановленный PWA стартовал с пустым хранилищем, Home-секции
  (`Текущий служебный год`, `Последние события`, итоги часов) были пусты.
- **Решение:** новая секция «Резервная копия данных» на экране Профиль
  (`app/(tabs)/profile.tsx`) — кнопки «Экспортировать данные» /
  «Импортировать данные». Экспортируются только 4 ключа, которыми владеет
  Ministry: `mj_records_v1`, `mj_events_v1`, `mj_talks_v1`, `mj_sessions_v1`.
  `mj_timer_v1` (control-state таймера, TASK_005C) **сознательно исключён**
  — не отчётная сущность, перенос между устройствами бессмысленен и рискован
  (ложный триггер Recovery Screen). Persisted-настроек в проекте пока нет —
  формат версионирован (`version: 1`) для будущего расширения.
- **Формат бэкапа:** версионированный JSON (`format: "ministry-backup"`,
  `version`, `createdAt`, `appVersion`, `data.{records,events,talks,sessions}`,
  `counts`) — `src/data/backup.ts`. `counts` в файле не доверяются, а
  пересчитываются из провалидированных массивов при импорте.
- **Валидация (до любой записи):** формат/версия/структура,
  строгая календарная дата `YYYY-MM-DD` (реальный день месяца, с учётом
  високосных лет, детерминированно по UTC) для `date` событий/речей/сессий;
  строгий ISO-datetime (обязательная таймзона) для
  `startTime`/`endTime`/`createdAt`/`updatedAt` сессий и `createdAt` бэкапа;
  запрет дублей id; лимиты размера payload и количества записей на
  категорию. Русские сообщения об ошибках без технических деталей.
- **Импорт:** предпросмотр (дата создания, версия формата, таблица
  «Сейчас/В файле» по 4 категориям) → явное подтверждение замены
  (`Заменить данные`) → `performImport()` (`src/data/backupImport.ts`):
  application-level snapshot (не физическая атомарность
  `AsyncStorage.multiSet`/`multiRemove` — зафиксировано явно в коде) →
  запись → контрольное чтение → откат к снимку при любом сбое записи или
  верификации (восстанавливает как существовавшие, так и ранее отсутствовавшие
  ключи). Успех репортится только после подтверждённой верификации;
  перезагрузка приложения — из колбэка `OK` алерта об успехе.
- **Веб-платформа:** `src/data/backupFile.web.ts` (Blob + `<a download>`
  для экспорта, скрытый `<input type=file>` + `FileReader` для импорта) /
  `src/data/backupFile.ts` (нативный fallback — throw «unsupported», без
  добавления нативных зависимостей под непроверенную на устройстве сборку).
  **Hardening (после первого ревью):** фолбэк отмены пикера через `window`
  `focus` — некоторые версии Safari/iOS не эмитят `cancel` у
  `<input type=file>`, из-за чего промис завис бы навсегда; при возврате
  фокуса даётся ~300мс на `change`, иначе — трактуется как отмена; флаг
  `fileSelected` защищает от гонки (поздний/случайный `cancel` не
  перебивает уже выбранный файл), `settled` гарантирует однократное
  разрешение промиса, `cleanup()` снимает все слушатели/таймер/DOM-узел на
  каждом пути завершения.
- **Ревью:** двойное независимое ревью (Opus) — финальный вердикт
  **APPROVED WITH NON-BLOCKING NOTES**. Незначительные, не блокирующие
  релиз замечания (устранение вне объёма по решению владельца):
  строгий ISO-datetime валидатор пропускает невозможный день при

#### TASK_013 (iOS PWA picker-фикс) — отложенный `change` терялся из-за 300мс focus-отмены — задеплоен, проверен в проде (read-only)

- **Проблема (обнаружена владельцем на реальном iPhone):** валидный
  бэкап был выбран в системном Files на установленном на экран «Домой»
  PWA; после возврата в приложение не появлялось ни предпросмотра, ни
  таблицы счётчиков, ни кнопки «Заменить данные», ни какой-либо ошибки
  — импорт не происходил вообще.
- **Причина:** `pickBackupFile()` в `src/data/backupFile.web.ts`
  возвращал одноразовый `Promise`, застрахованный 300мс таймером-
  фолбэком на `window.focus` (введён ранее как защита от Safari-версий,
  не эмитящих `cancel`). На iOS PWA фокус окна может вернуться из Files
  раньше, чем браузер успевает диспатчить `change` у `<input
  type=file>`. Таймер отклонял Promise как `cancelled`, а
  `cleanup()` в этот же момент снимал все слушатели и удалял `<input>`
  из DOM — пришедшее позже настоящее событие `change` попадало на уже
  отсоединённый, безслушательный узел и терялось без следа (без ошибки,
  так как `BackupSection` трактовал `cancelled` как молчаливую отмену).
- **Исправление:** `src/data/backupFile.web.ts` — пикер переведён с
  одноразового Promise на постоянный (module-owned singleton, создаётся
  лениво один раз и живёт весь срок жизни страницы) скрытый `<input>` с
  callback-API (`onSelected`/`onError`/`onCancelled`) вместо
  `Promise<string>`. Фокус-эвристика и явное событие `cancel` теперь
  лишь неразрушающе сигнализируют UI («можно снять индикатор
  загрузки») через `onCancelled` — они никогда не отклоняют, не
  уничтожают и не settle'ят уже начатый выбор; отложенное на 301мс, 1с
  и дольше `change` по-прежнему доходит до `onSelected`, даже после
  того как `onCancelled` уже сработал. `input.value` сбрасывается сразу
  после каждой обработки — тот же файл можно выбрать повторно.
  `src/data/backupFile.ts` — нативный fallback переведён на тот же
  callback-сигнатуру (синхронно вызывает `onError("platform-
  unsupported")`). `src/components/settings/BackupSection.tsx` —
  `handlePickImport()` переписан вокруг callback-API вместо
  `await`/`try`/`finally`; добавлен `mountedRef`-guard против записи
  состояния в размонтированный компонент отложенным колбэком.
- **Ревью:** независимое ревью (Opus) — **APPROVED WITH NON-BLOCKING
  NOTES**. Единственное отмеченное (не блокирующее) замечание: при
  очень быстром повторном нажатии «Импортировать данные» в узком окне
  между срабатыванием `onCancelled` и приходом отложенного `change`
  предыдущей попытки, событие `change` может быть отнесено к колбэкам
  новой (текущей) попытки — реальный выбранный файл при этом никогда
  не теряется и не подменяется, влияет только на то, к какому именно
  вызову он будет отнесён; предпросмотр и явное подтверждение
